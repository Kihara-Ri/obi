# 2026-11-21 · 「更多」子页转屏后整屏点不动（防护）

- **作者**：Claude
- **范围**：`web/src/core/edge-swipe.ts`、`web/tests/pwa-guards.test.mjs`、`web/src/components/AppNav.tsx`

## 出现的问题
- 用户反馈：主屏幕 App 在「更多」里的页面（如交易记录）横屏再转回竖屏后，整屏点不动也滑不动，切出应用也不恢复，只能杀掉重开。

## 分析
- 只有「更多」子页装了左缘右划返回（`core/edge-swipe.ts`），它在左缘 28px 内的 touchstart 上就 `preventDefault`，这会同时吞掉点击和滚动。
- 转屏期间 / 之后若 iOS 给的触点坐标与实际按到的元素对不上，每一下都可能被当成左缘起手拦掉，表现正是「完全不动、只在更多子页」。
- 桌面 Chromium 模拟横竖屏复现不出（没有 iOS 的转屏时序），这是最吻合症状的推断，尚未在真机确认。

## 改了什么
- 转屏（`resize` / `orientationchange`）时收掉进行中的左缘手势，之后 800ms 内不接管。
- 触点坐标在视口外，或该坐标处的元素与实际按到的元素对不上时，不拦截、放行。
- 正常的左缘右划返回不变。

## 怎么验证的
- 预览手机尺寸交易记录页：模拟左缘右划，仍能返回「更多」；派发 resize 后立即起手，不再接管。
- 前端单测（守卫测试补了转屏防护断言）、类型检查、构建、后端测试、文档检查、浏览器验收通过。
- 待用户真机确认：横屏再转回竖屏后是否还会卡住。

## 可能带来的新问题
- 转屏后 0.8 秒内从左缘右划不会触发返回（交给系统）。
- 若真机仍卡住，说明原因不在手势拦截，需要连 Mac Safari 网页检查器看卡住时的状态。

## 追加：「更多」页转屏后底栏点不动
- 用户确认子页不再卡死，但在「更多」页横屏再转回竖屏后，底栏几个图标点不动；点进更多里的某项再退回来又能点。
- 推断：iOS 转屏后，固定定位且带背景模糊（独立合成层）的底栏点击区域停在旧位置，要等整页重排才更新；「更多」页内容短、不滚动，没有别的东西触发重排，切页动画会。
- 改法：`MobileNav` 监听 `orientationchange` / `resize`，转屏停下 350ms 后把底栏原地重建一次（同一帧内 `display:none` → 读一次布局 → 还原，不闪）。
- 中途试过横屏时盖「请转回竖屏」的全屏提示，用户不要，已整体撤掉，没有留下改动。
- 验证：预览手机尺寸「更多」页派发转屏事件后底栏样式完好、点「库存」能切页；真机效果待用户确认。
