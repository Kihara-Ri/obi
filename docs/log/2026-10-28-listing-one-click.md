# 2026-10-28 · AI 一键准备上架资料

- **范围**：售卖辅助任务、模型适配、草稿事务、全局风格预设与上架资料抽屉；用户先确认方案后实现（D-031）。

## 改了什么

- 一次点击自动整理已有发行资料、核对实物、调用模型生成标题与正文；不再次查询发行版，不再逐项勾选确认。
- 无实物照片仍可生成，未知品相明确保留；照片观察引用本副本照片编号，冲突和待核实事项单独展示。
- 分析与写作分成两次调用，换风格与失败重试复用有效分析；资料、照片或本次补充变化则失效，可从分析依据强制重新核对。
- 新草稿自动事务保存；已有文案或本次编辑先展示候选，采用后才替换。照片/记录 revision 防并发覆盖，保存与标记上架继续分开。
- 三种内置风格与自定义预设，全局默认使用简洁直售；偏好 revision、完整备份恢复校验与模块保护保持一致。
- 白名单上下文包含发行资料、必要副本属性与用户本次补充，排除采购字段、私人备注及数字实体。分析保留上下文快照与所用预设，不伪造人工确认。
- 仅文字模型用于无照片场景；多服务商原授权、任务快照与失败不切换计费来源的边界保留。兼容 CLI 的纯文字写作输入与模型 JSON 代码围栏。
- 同步 AGENTS、决定、使用/部署说明、组件注册表与模块契约；新场景全部复用固定 21 副本，增加样本覆盖断言。

## 遇到的问题与处理

- Linux 环境没有 npm 的默认 PATH；使用已有 Node 安装及锁文件安装前端依赖，未升级依赖。
- 系统 Docker 缺 compose 子命令与新版 buildx，使用已安装 docker-compose 的经典构建路径；不改部署配置。
- /private/tmp 不可写，使用独立 /tmp 样本目录。售卖参考照片初始化会改变照片 revision，影响模型样本有效性，因此完整预览与售卖协议验收使用两个独立固定样本实例，共用已校验素材包。
- 验收脚本在抽屉关闭动画与 history.go 完成前切换 hash，路由被异步返回撤销；脚本等待真实 popstate 和抽屉卸载，不改已有抽屉行为。
- 一轮验证把清理静态文件的前端构建与读取静态文件的后端测试同时运行，造成临时 404/文档路径缺失；后续按构建完成后再跑全量后端测试执行。

## 后续边界

- 首次生成消耗两次模型调用；只写文案时一次。风格只控制表达，不能新增事实或承诺。
