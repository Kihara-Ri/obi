# 2026-10-29 · 闲鱼文案优化：去掉不确定措辞、标题符号、首图

- **作者**：Claude

## 改了什么
用户给出的闲鱼实际情况：无单独标题框；标题里的书名号等符号易被截断或省略；首图影响展示；不标成色但描述里要用恰当用语；DeepSeek 写文案总说“不确定、需要看了再说”，这些不该给买家看。
- 提示词重写：标题是描述第一行，不含书名号 / 括号 / 引号 / 表情；纯文本、版本和实物状态靠前；严禁不确定措辞；品相为空整段不写；成色用具体克制的日常用语，不写等级。
- **根因**：写作模型拿到了内部清单——`pending`、`conflicts`、「实物品相尚未核实」，提示词还写着“保留品相未核实的事实”。现在这些都不再传给写作模型，只传 `versionConflict` 布尔值，品相未知时 conditionText 传空。
- 兜底：写作后检测不确定词，有就带着命中词重写一次，仍有则整句删除；标题再统一清掉括号引号和结尾标点。“可能 / 或许 / 大概”只触发重写，不删句。
- 首图：实物照片首张标「首图」，其他张「设首图」；顺序存在草稿 `photoOrder`（已有字段），已保存草稿直接保存，否则并入草稿待保存；「保存图片」与 ZIP 按此顺序，文件名序号按新顺序；重新生成沿用已设顺序（照片没变且是完整排列时）。

## 出现的问题
- 「设首图」按钮误用了复制按钮的圆形样式：把复制按钮样式限定到 `.listing-photo-copy`。
- 旧验收脚本断言文案含「尚未核实」，与新要求相反：改为断言不含。

## 怎么解决的
被放弃的方案：只靠提示词禁止——模型仍会把内部清单里的话抄出来，所以先切断输入，再加检测与删句兜底。

## 可能带来的新问题
- 含“不确定”字样的句子会被整句删除：句子里夹着的真实信息会一起丢，但宁可少写也不给买家看含糊话。
- 品相未知时文案没有品相段，买家可能追问；这是用户确认的取舍。
- 闲鱼标题 / 描述的字数上限与图片张数上限未确认，没有加限制。
- 已验证：后端 listing 两个测试模块（含输入隔离、重写一次、整句删除、标题清洗）、前端构建、浏览器 390 宽设首图与保存后重开顺序保持；真实模型（尤其 DeepSeek）的实际输出未验，需真机生成几次看。
