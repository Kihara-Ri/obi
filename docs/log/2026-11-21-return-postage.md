# 2026-11-21 · 退货可另记寄回运费

- **作者**：Claude
- **范围**：`domain.py`（`set_return_postage`）、`storage.py`（利润计算、`sale_action` 退货 / 撤销退款 / 新操作 `return_postage`、备份恢复校验）、`server/export_csv.py`、`web/src/forms/ConfirmForm.tsx`、`web/src/pages/SaleCard.tsx`、`web/src/types.ts`、`tests/test_sale_undo_refund.py`

## 改了什么
- 「已发货 · 退货」时多一个可选的**寄回运费**（人民币）：买家退回专辑、运费由自己承担时填，买家承担就留空。和寄出运费分开记，两趟可以不一样。
- 寄回运费记在销售单上（`returnPostage`），多张合单按件均分；每件到手 = 成交 − 扣费 − 寄出运费 − 退款 − 寄回运费，已退货的利润就是这个数，即损失里多算了寄回运费。
- 已退货的交易卡片多一个「填寄回运费 / 修改寄回运费」按钮，事后可补填、修改或清空。
- 交易卡片的费用行在已退款 / 已退货时补上「− 退款」，有寄回运费时补上「− 寄回运费」，算式能对上到手与利润。
- 撤销退款时寄回运费一并清空；仅退款（买家留着专辑）、未发货退款不收寄回运费。
- CSV 交易导出加「寄回运费」列；备份恢复校验覆盖这个字段。

## 出现的问题
- 用户反馈：退货退款时，除了寄出去的邮费，有时也得自己承担寄回来的邮费，两趟金额可能不同，原来没处记。

## 怎么验证的
- 新增后端测试：退货填寄回运费、两件均分（4.50 / 4.51）、利润含两趟运费；事后修改、清空；撤销退款后清空；售出中不能填；仅退款忽略。
- 示例预览：售出中一笔走「已发货 · 退货」填 8.5，卡片显示 `− 退款 ¥88.00 − 寄回运费 ¥8.50`、利润 ¥-12.90；再改成 10，利润 ¥-14.40。测试前备份示例数据，测完已恢复。
- 前端单测、类型检查、构建、后端测试、文档检查、浏览器验收通过。

## 可能带来的新问题
- 寄回运费固定按人民币记（与退款金额同口径），日元交易的寄回运费也要折成人民币填。
