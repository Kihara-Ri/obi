# 2026-11-17 · 撤销退款 / 退货

## 问题与处理

用户把一笔应「仅退款」的交易误操作成「退货」（专辑被退回库存），界面上没有撤销入口。新增 sale-action `undo_refund`（`storage.py` `sale_action`）：只允许已退款 / 已退货的交易；交易回到售出中，去掉退款日期与各项退款金额，写审计；已退货时把退回国内库存的专辑改回售出中并重新挂上 `saleId`，若任一专辑已不在国内库存或已被别的交易占用则拒绝。前端在交易记录的已退款 / 已退货卡片上加「撤销退款」（`SaleCard`），走通用确认抽屉（`ConfirmForm` 新增 `undo_refund` 文案）。`界面与功能定案.md` 已补条目。

## 验证与风险

新增 `tests/test_sale_undo_refund.py`（撤销退货后专辑回到售出中、再改走仅退款；撤销退款保留专辑；专辑再次售出后拒绝；售出中的交易拒绝），与 `tests.test_ledger` 共 78 项通过；前端类型检查与构建通过。固定样本手机视口：退款后退货、在「已退货」点撤销退款并确认，交易回到售出中，控制台无错误。撤销后汇率、费用沿用原交易记录，不重算；退款时若已产生其他手工账目调整需用户自行核对。

## 追加：退款与退货拆成两个场景

用户说明两者是不同场景：退货是买家收到后退回、自己损失运费；退款是还没发货。原抽屉是「退款总额 + 勾选恢复库存」，未勾选时专辑留在售出中（等于买家留着专辑），与用户的「未发货退款」不符，也容易点错。抽屉改为 `Seg` 二选一（还没发货 · 退款 / 已发货 · 退货），默认不选、确认钮禁用；按钮文字随场景变为「确认退款 / 确认退货」。后端 `refund` 新增 `unshipped`：专辑回到 `previousStatus`（海外 / 国内），销售单与各项的平台扣费、寄出运费（含日元原币）存入 `refundKeptCosts` 后清零，利润按退货口径（不扣成本）；撤销时恢复费用。交易卡片对未发货退款标「未发货退款」。旧版「仅退款、买家留专辑」不再从界面提供，旧数据照常显示与撤销。新增 3 项后端测试（共 80 项含 `test_ledger`），前端 189 项、类型检查与构建通过；手机视口实测：未选场景时确认禁用，未发货退款后专辑回国内库存、扣费与运费为 0、利润 0，撤销后扣费恢复 4.40，控制台无错误。部分退款的未发货场景（退款小于成交价）余额会计入收入，按实际很少见，未单独处理。
