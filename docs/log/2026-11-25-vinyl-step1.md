# 2026-11-25 · 黑胶支持第 1 步：能把黑胶录进来

- **作者**：Claude
- **范围**：`domain.py`、`server/release_catalog.py`、`server/discogs_catalog.py`、`server/text_search.py`、`covers.py`、`server/routes.py`；前端 `core/medium.ts`、`core/lookup.ts`、`core/tracklist.ts`、`core/lookup-text.ts`、`core/version-cover.ts`、`forms/record/useReleaseLookup.ts`、`forms/record/ReleaseLookupSection.tsx`、`forms/record/pickRelease.ts`、`pages/LookupPage.tsx`、`pages/AlbumResults.tsx`、`pages/LookupCard.tsx`、`components/Tracklist.tsx`；样本库 `tools/seed_samples.py`；测试与文档。

## 改了什么
专辑表单和「查询」页加「CD / 黑胶 / 其他」选择，查询、版本核对、Discogs、文字搜索展开版本和封面退路都按所选介质找；黑胶曲目带面编号（A1、B2），碟名用格式。样本库加 `seed_vinyl_review`（`--vinyl`），把三张现有副本换成 12″ LP、带侧标的日版 2LP 和 7″ 单曲。

## 出现的问题
- 原来的「非 CD 报错」写在 MusicBrainz 和 Discogs 的详情读取里，保存时的身份核对也走这条路；直接改成按介质核对会让已存黑胶无法保存。
- Deezer / iTunes 的候选不写介质，按介质核对会把它们全拒掉。
- `release-details` 的查询参数缺省时一开始也按 CD 处理，查询页展开黑胶候选的详情会报错。

## 怎么解决的
- 介质核对挪到 `ReleaseCatalog.release_details(ident, medium=None)`：只有调用方带了介质才核对，保存核对和查询页展开详情不带；格式列表为空（数字发行来源）时不核对。路由里 `clean_medium(q.get('medium'), None)`。
- 介质不新增字段，从格式推出（D-053），旧记录不迁移；放弃了「新增 `medium` 字段 + 迁移」，因为格式里已有足够信息，且外部接口不用变。
- 样本库没有加新副本：新副本要配真实封面并改素材锁，这里改为复用三张现有副本（和 `seed_purchase_review` 同样的做法）。

## 可能带来的新问题
- 黑胶的包装预设、尺寸 / 转速等规格、品相分级、列表筛选和采购评估的明确介质口径都还没做（方案第 2–4 步）；黑胶暂选「其他包装」。
- 介质靠文字识别，资料里只写 `Record` 等罕见写法会算成「其他」。
- 已验证：Python 全量 612 项通过、前端单测 206 项（含新 `medium.test.mjs`）、typecheck 与 build 通过；浏览器验收见提交前记录。
