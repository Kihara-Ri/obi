# 2026-11-03 · 照片切换加日志：提交即生效，中途退出下次启动补完

- **作者**：Claude
- **范围**：`storage.py`（`save` 写切换日志、`apply_photos` 幂等、新增 `finish_photo_swaps`、`Store.__init__` 启动补完）、`tests/test_photo_swap.py`、D-036

## 出现的问题
11-02 的暂存 + 改名把「写到一半」消除了，但还剩两个窗口：账本已提交、目录还没改名时进程退出（记录是新照片、磁盘是旧照片）；两次改名之间退出（记录的照片目录不存在）。复盘时考虑过改成内容寻址文件，但那要改 `data/photos/<id>/<序号>` 的磁盘布局，牵动读图、备份、售卖下载、样本工具与真实数据迁移。

## 怎么解决的
不改布局，加一条前滚日志：每次带照片的保存在同一事务里写 meta `photo-swap:<暂存目录>` → 记录 id，提交后切换并删除这几行；`Store` 启动时把残留的日志行逐个补完。`apply_photos` 改为幂等：暂存目录还在就继续改名，已不在说明已换上，只清旧目录。于是账本提交是新照片生效的唯一时点。

## 可能带来的新问题
- 每次带照片的保存多一次极小的写事务（删日志行），state 指纹会多变一次，客户端仍按 ETag 拿到 304。
- 运行中两次改名之间仍有微秒级的「目录不存在」，这期间的读图请求会 404，刷新即好；崩溃一致性已由日志保证。

## 验证
新增 3 项测试：正常保存不留日志；模拟提交后退出、两次改名之间退出，重新打开 `Store` 后照片、`photoCount`、日志与暂存目录均正确。后端 584 项全绿。
