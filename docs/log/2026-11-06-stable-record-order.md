# 2026-11-06 · 同日副本顺序与录入时间

- **作者**：Codex
- **范围**：storage.py 的 records 读取/更新、管理页只读字段、回归测试及使用文档。

## 问题与修复

库存同日购买记录依赖输入数组的稳定排序；原先 SELECT 未指定顺序，INSERT OR REPLACE 又会删除旧行并新插，导致保存后全量刷新换位。固定样本 Dookie / Parachutes 在只改备注后可复现。

records 读取显式 ORDER BY rowid，写入改为 ON CONFLICT DO UPDATE，保留数据库既有行位置；新记录自然接在末尾。备份按同一顺序导出、恢复依序插入，保持相对次序。sales / shipments 的写入行为未变。无需 schema 迁移、历史回填或新增可编辑排序字段。

管理页复用 Rows 显示原有 createdAt，编辑保持原值；缺失显示「未记录」。购买日期、艺人、成本等排序依据仍正常生效。

## 边界与可能的新问题

沿用升级时现有顺序，不推测或恢复修复前曾经丢失的历史位置。主动修改购买日期、排序方式或改变同专辑分组身份，仍可能按对应规则调整展示位置。数据库文件被外部工具重建且改变插入顺序不在应用保存契约内。

本地实现阶段未触碰真实 data。用户随后授权服务器部署，日常构建号发布，不打 tag、不推送；部署工具在停服务后生成快照，再切换软链并进行健康检查，失败自动回滚。部署前只读记录副本 ID 次序与录入时间的合并摘要，供部署后核对。手机宽度模拟不代表真机验收。原工作区已有其他改动，不纳入本次独立发布。
