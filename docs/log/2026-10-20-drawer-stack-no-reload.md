# 2026-10-20 · 抽屉页面栈常驻：从二级页返回不再重新加载

- **作者**：Claude
- **范围**：`web/src/components/ui/Drawer.tsx`、`App.tsx`、`forms/DetailDrawer.tsx`、`forms/detail/{ReleasePage,ManagePage}.tsx`、`forms/ArtistDrawer.tsx`、`styles/drawer.css`、`web/tests/twin-controls.test.mjs`

## 问题
进入发行资料 / 管理 / 编辑 / 艺人页再返回，上一层会闪一下或动画重放。根因有两层：
1. 返回按钮调用 `openDetail(...)` / `openArtistDrawer(...)`，等于**再开一个新的详情页**：旧的组件树被销毁、新的重建，详情里的爱心请求、照片预取、封面解码、艺人页的目录请求全部重新跑一遍，所以看起来「重新加载」。
2. 上一版动画用 DOM 克隆（快照）当离场的旧页：快照只是静止图像，返回时真正的页面是新挂载的，与快照切换时会有一帧差异。

## 改了什么
- **页面栈常驻**：`App` 把抽屉栈作为 state 传给 `Drawer`（`pages`）；`Drawer` 把栈里**每一层**都渲染成一个 `.drawer-page`，以稳定 id 作 React key，进入二级页时下面那层原样保留（只是被盖住：`is-covered`，不可见、`inert`），返回 = 弹栈露出它，**不销毁、不重建、不重新请求**。
- **动画直接作用在真实节点上**，不再克隆快照：返回时被弹出的页面作为 `is-leaving` 层保留到动画结束再卸载；下层在动画期间保持可见（`is-animating`）才能看到视差 / 缩小。
- 发行资料页、管理页、艺人页 ↔ 详情的「返回」全部改成 `app.backDrawer()`（弹栈），不再调用 `openDetail` / `openArtistDrawer`；从艺人页进详情又点同一位艺人也是弹栈。
- 删掉 `captureGhost` / `ghostRef`。

## 验证
- **加了一个临时计数器**（只在验证时存在，已还原）数详情页爱心请求次数：打开详情 = 1；进入发行资料再返回 = 修复前 **2**，修复后 **1**；再进管理页再返回、进编辑再取消，仍是 1。
- iPhone 模拟器：艺人页选「EP」分类并滚到底，展开「未关联的本地副本」→ 点「详情」→ 返回，艺人页仍停在 EP、滚动位置与展开状态不变。
- 前端 131 项测试（新增一条回归断言：返回按钮不再调用 openDetail，Drawer 以 `layer.id` 作 key）、类型检查、构建通过。

## 没验证 / 限制
- 动画在栈常驻后改成真实节点参与，只做了行为验证（内容不重载、位置保留），没有再逐帧确认四种动画的视觉；返回的边缘右滑（手势）在本次也没单独重测。
- 栈里每层都常驻，艺人页这类重页面叠在详情上面时两层都占内存，抽屉关闭时一起卸载；单次会话里通常只有 2–3 层。
- 未部署。
