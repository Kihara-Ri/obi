# 2026-10-20 · 表单「取消」回到上一层，不再关闭整个抽屉

- **作者**：Claude
- **范围**：`web/src/App.tsx`（`backDrawer`）、`state/AppContext.ts`、`components/ui/Drawer.tsx`、`forms/{RecordForm,ListingForm,SaleForm,SaleCostsForm,ConfirmForm,ShipForm}.tsx`

## 问题
详情 → 编辑、详情 → 管理 → 编辑上架资料，点「取消」都直接关掉整个抽屉，而不是回到打开它们的上一层。原因：所有取消键调用 `app.closeDrawer()`（关闭整个抽屉）；加了二级页和任务页之后，抽屉里有了真正的层级，取消语义没跟着改。

## 改了什么
- 新增 `app.backDrawer()`：抽屉栈里还有上一层就回到上一层，没有才关闭（从列表直接打开的表单取消仍然关闭）。有未保存修改时先走原来的放弃确认；回退按「返回」方向播动画；程序性退掉对应的浏览器历史条目（`popGuard` 忽略随之而来的 popstate，避免再弹一层）。
- 6 个表单（编辑、上架资料、记录售出、销售费用、确认类、运输）的「取消」改用 `backDrawer`。
- 任务页取消的动画：离场页淡出下沉 10px、上一页淡入（`Drawer` 记住离场页是任务页还是下钻页），与进入时的「淡入上浮」对称，不做横向滑动。

## 没改（有意）
- 右上角 × 与 Esc 仍关闭整个抽屉。
- 记录售出、运输、销售费用、确认类表单保存后，以及移除、调回海外（`bulkAction`）仍关闭整个抽屉：这些操作之后这张专辑的状态可能已变，回到详情会是过期内容。

## 验证
iPhone 模拟器：详情 → 编辑 → 取消 → 回到详情；详情 → 管理 → 编辑上架资料 → 取消 → 回到管理页（带返回箭头）；返回后点 × 关闭，页面仍在原来的列表，历史没有错乱。前端 128 项测试、类型检查、构建通过。未验证：带未保存修改时取消的确认弹窗分支。未部署。

## 追加：编辑保存成功后回到上一层（用户决定）
- `useFormSubmit.run` 新增 `{backOnSave}` 选项：先 `refresh()` 再 `backDrawer(true)`（`backDrawer` 新增 `force`：保存成功后跳过放弃确认，没有上一层时等价于关闭），所以上一层（详情 / 管理页）出现时已经是更新后的内容。
- 启用：编辑专辑（仅编辑已有专辑，新增仍关闭）、上架资料（保存草稿、保存并标记上架，回到管理页）。
- 验证：iPhone 模拟器里详情 → 编辑 → 在「备注 · 这张副本」输入 → 保存修改，回到详情，备注摘要立即显示新内容；键盘遮挡修复仍有效。前端 128 项测试、类型检查、构建通过。
- 未验证：上架资料保存后回到管理页（代码路径与编辑相同，只验了编辑）。未验证的还有保存失败时留在表单并显示错误（沿用原逻辑未改）。
