# 2026-10-30 · 编辑保存不调用汇率模块

用户明确：单纯编辑专辑不涉及金额，没有必要调用汇率模块。本次落实此边界，替代上一条诊断日志中编辑后刷新完整账本的做法；此前失败冷却仍用于其他正常财务刷新。

## 修改

- `POST /api/records/metadata` 只保存已有记录的标题、艺人、发行资料、包装、侧标、封面、存放位置、笔记和照片；拒绝金额、币种、日期、费用、渠道、状态与批量 / 新增输入。继续复用身份校验、写锁、revision 和 `Store.save`，不绕过事务。
- 保存完成后从数据库返回规范化资料、照片数量 / 版本和最近审计；同专辑共享笔记涉及的副本也返回。此路径不调用 `Store.state`、`record_rates` 或汇率服务，包括 status / warm / get。
- 前端只提交元数据，通过 AppContext 合并确认结果，直接返回已更新的详情，不再调用 `app.refresh`。金额、成本、利润、状态与包裹 / 交易关系保留已有结果，成本 null 不当 0。
- 账本状态 hook 从 App 内抽出，仍是同一个上下文状态源。合并后清掉旧 ETag，下一次普通同步拉完整状态；在保存之前发起、之后才返回的刷新丢弃，避免还原刚保存的资料。
- 新增入库、PurchaseForm 与其他财务操作沿用原接口与刷新逻辑。条码 / 来源改变时仍做身份核对，照片上传仍使用原协议；本次没有实现预上传或二进制上传。

## 验证

- 后端新增 5 个固定样本回归：汇率服务设为调用任何方法就失败，资料 / 照片保存仍成功；共享笔记两副本回传；金额字段拒绝；无效照片 / 旧 revision 不写入；不接受新增 / 批量。固定样本骨架不另造，照片使用样本库的离线协议夹具。
- 前端新增 3 个回归：规范化资料和照片回显、清除移除的可选元数据、共享笔记更新；保留已知 / 未知成本及交易利润；旧响应不回退较新记录；编辑载荷不带任何财务字段。
- 后端全套 558 项、前端 168 项通过；typecheck / 生产 build 通过，构建仍有已有的 theme.js 与大 chunk 提示；`test_local_entry` 通过，共用路由没有本机模式分叉。
- 浏览器 390×844：日元副本编辑备注保存，仅有 `/api/records/metadata` 请求，无 `/api/state` / `/api/rate`，响应约 10 ms，详情笔记立即回显，买入金额 / 折算显示不变。再新增一张锁定参考照片保存，只有元数据请求与详情照片读取，无财务请求，照片数量 / photoRevision 回显正确，响应约 17 ms。以上为本机回环，不代表手机 4G。
- console error / warning 为 0。样本从已有锁定素材离线重建独立临时实例，未修改真实 data；此前用于编辑的样本实例已因照片变更使实体失效，因此没有绕过素材检查继续启动它。
