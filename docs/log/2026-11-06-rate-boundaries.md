# 2026-11-06 · 汇率读取、准备和入账分离

- **作者**：Codex
- **基线**：已部署的 7458adc；本次在独立分支 refactor/rate-boundaries 实现，不混入主工作区其他未提交改动。

## 改了什么

- RateService 拆出标准库 provider/cache，仅读报价与显式准备分开；未来日期不返回数值，回退必须有覆盖且不超过14天。近期报价按300秒及跨午夜失效，错误有供应商级冷却，慢查询不阻挡有效缓存读取。
- Store.state/CSV 仅读同一缓存快照，金额及报价说明保持一致；缺报价由客户端独立准备、分窗口推进后刷新。即使 state 回304，也可在传输失败后到期重试；空结果和无进展不会形成请求循环。
- 财务报价在全局写锁和业务事务之外准备；锁内核验单据快照、报价有效性并用Decimal入账。包裹日期变化按用户选择重算并分摊；仅增减成员总额不变。日元入账保留rateQuote，销售费用沿用已记录依据。派生采购报价不接受表单伪造。
- 前端统一报价hook，按需启用、切日期移除旧值并取消旧请求；未来/失败保留输入，零运费无需等待报价。
- 本机net/main通过限定session与请求ID同步，主缓存回传规范结果，超时/旧回执受控；ACK仅表示主会话SQLite接收，公开缓存可丢失重取，不扩展旧财务落盘承诺。服务端没有客户端报价导入接口。
- 固定样本假汇率改成完整日覆盖，保持既有金额断言；新增seed_rate_review复用现有Dookie制造缺缓存场景。补丁包根文件白名单、用户文档、D-043和汇率契约同步更新。
