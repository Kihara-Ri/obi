# CI 提速与浏览器验收去抖

- **作者**：Claude
- **范围**：`.github/workflows/ci.yml`、`tools/run_tests.py`（新）、`tools/sample_bundle.py`、`web/tests/browser/showcase-acceptance.mjs`、`web/tests/browser/listing-acceptance.mjs`、`deploy.toml`、`AGENTS.md`、`README.md`、`web/tests/browser/README.md`

## 改了什么
- 后端测试改用 `tools/run_tests.py`：每个测试模块一个进程并行跑，慢模块先开跑；测试集与 `unittest discover` 相同（465 项）。本机 60s → 17s。发布前的测试关卡（`deploy.toml`）同步改用它。
- 浏览器验收从一个 job 拆成三个并行 runner：`card,mobile`、`models`、售卖草稿。`showcase-acceptance.mjs` 新增 `--parts`（图库检查总会先跑），每项结果带 `ms`，方便以后按耗时重新分片。
- Playwright Chromium 加缓存；样本素材缓存加 `restore-keys`。
- 样本下载遇到网络错误或字节不符时退避重试（1s / 2s / 4s），仍只接受锁定哈希的字节（I-013 缓解）。

## 出现的问题
- v3.0.0 之后 main 的 CI 红在售卖验收：`openProvider('DeepSeek')` 用 `isVisible()` 判断是否要展开「切换或添加服务商」，但折叠区收起时仍挂载（grid 行高 0、透明度 0），Playwright 判为可见，于是直接点了折叠区里的行，点击一直被上方的展开按钮拦截，30s 超时。本机时序不同没复现。

## 怎么解决的
- 按行是否位于折叠区、展开按钮 `aria-expanded` 来决定是否展开，展开后等 `.collapse.is-open` 再点；先等列表读完，避免在「正在读取识别配置…」时判断。
- 被放弃的方案：给点击加 `force: true`（会掩盖真实的不可点问题）。

## 可能带来的新问题
- 三个浏览器 runner 各自装依赖、准备样本，总分钟数变多，墙钟变短；公开仓库不计费。
- `run_tests.py` 让各模块并发运行：若以后有测试共用固定端口或固定临时路径，会在并行时互相干扰，需改成随机端口 / 独立临时目录，或用 `-j 1` 排查。
- 售卖验收脚本对同一实例重跑会失败（第一次已保存密钥，第二次找不到输入框）；CI 每次是新实例，不受影响。
