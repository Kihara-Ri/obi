# 2026-10-19 · 发布工具抽成 ai-kit 的 ship

- **作者**：Claude
- **范围**：ai-kit 仓库（本机 `个性化/ai-kit`，未提交）：`template/.ai-kit/ship/{ship.py,README.md,deploy.toml.example}`、`tests/test_ship.py`、`install.sh`、`CHANGELOG.md`、`README.md`、`template/.ai-kit/{VERSION,kit-files.txt}`（0.3.0）；本项目：`deploy.toml`（新）、`tools/deploy.sh`（改为兼容层）、`tools/package_app.py`、`tools/update_release.py`、`tests/test_updates.py`、`.ai-kit/`（经 ai-kit 升级流程装入 0.3.0）、`部署说明.md`、`docs/DECISIONS.md`（D-011）

## 改了什么
- ship：Python 标准库的单文件发布工具，子命令 `deploy / rollback / unlock / status`；配置 `deploy.toml`，个人覆盖 `deploy.local.toml`（路径可用 `[config] local` 改），环境变量 `SHIP_*` 优先；数据库用 `kind = "none" | "sqlite" | "command"`，其余流程与 D-010 一致（预检、产物一致性、快照轮换、按 schema 恢复、锁、`deploy.log`、公网检查、ssh 复用）。
- 新增：`ship status`；手动回滚改为「当前版本的前一个」，连续回滚会继续往前走，不再在最新两版之间来回切。
- 本项目：`tools/deploy.sh` 只做旧参数 / 环境变量到 ship 的翻译；补丁更新器的调用方式、退出码与提示文字不变，原有 19 个流程测试原样通过。
- 发布包新增 `deploy.toml` 与 `.ai-kit/ship/ship.py`，`PACKAGE_ROOTS` 与必需文件同步（补丁更新器在服务器上运行时要用）。

## 出现的问题
- 测试隔离：改写测试时，「从配置文件读主机」那条用例没设个人覆盖路径，读到了本机真实的 `data/deploy.local.toml`（主机是真实服务器），于是把测试的临时目录当成发布目录通过 ssh 在服务器上执行：`sudo mkdir -p` 在服务器上建了 `/var/folders/...` 一串空目录，其余命令因权限失败，没有碰 `/opt/diedu`。已用 `rmdir` 只删了这串空目录并确认 `current`、发布锁都没变。
- 处理：测试夹具统一把 `SHIP_LOCAL_CONFIG` 指向不存在的文件，永远不读真实个人覆盖。
- 全角字符紧跟变量的老问题在新的兼容层里又出现一次（`$SHIP（…`），被测试的 UTF-8 解码直接抓到，已改为 `${SHIP}`。

## 可能带来的新问题
- 服务器运行 ship 需要 Python 3.11+（tomllib）：当前服务器是 3.13，已确认；其他环境要自行核对。
- 下次发布会把 `.ai-kit/ship/ship.py` 与 `deploy.toml` 一并带上服务器；补丁更新器的真实路径仍没在服务器上跑过，只在夹具里覆盖。
- ai-kit 仓库的改动没有提交也没有推送；本项目装入的 0.3.0 来自本地工作区，不是 GitHub 上的版本。

- 提交时钩子失效：`install.sh --update` 无条件把 `core.hooksPath` 改成 `.githooks`，覆盖了本项目的 `tools/hooks`（数据泄漏扫描 + 治理文档检查 + ai-kit 检查），所以这次提交没有经过泄漏扫描；CI 的泄漏扫描随后在本日志里抓到服务器主机名。已把日志里的主机名改成通用说法，`core.hooksPath` 恢复为 `tools/hooks`；ai-kit 的安装脚本改为「已设置其他 hooksPath 时只提示、不覆盖」。
