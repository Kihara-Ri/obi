# 2026-10-28 · 上架页以文案与取图为主

## 改了什么

- 根据用户对实际截图的反馈重排上架 UI：标题、正文作为首屏主体，默认阅读态，点编辑再出现输入框。底栏常驻“保存图片 / 复制文案”；生成设置、补充、核对依据与发布记录收起，明确版本冲突仍有独立提示。
- 新文案候选在文案位置预览，原稿保存规则不变；复制当前预览不等于采用或标记上架。
- 本副本实物照片以小图条展示，单张复制全尺寸 PNG；全部保存与详情复用 PhotoDownload，支持手机预取后在同一点击手势分享、桌面下载原格式 ZIP。
- 扩展既有 CopyButton 的文字按钮样式，不另造复制逻辑；照片预取结果由缩略图和保存入口共用。
- 照片读取支持可选 photoRevision 校验，和照片写入共用锁，防止并发读取混合照片；旧详情不带参数的地址继续可用。
- 记录 D-032，更新规范、使用/部署说明与组件注册表；新增图片剪贴板和照片版本测试。

## 问题与解决

- 原实现把流程与配置排在结果之前，正确的生成流程仍没有服务于“直接复制去发布”；本次按主要操作重新组织，而不只缩小旧卡片。
- 闲鱼官方反馈页明确支持粘贴截图，但没有证据证明商品发布页及手机 App 通用支持。匿名发布页被访问拦截；只读取官方公开发布脚本，未登录、未上传或发布。不把反馈页能力当成发布能力。
- 标准图片剪贴板不能可靠批量写入，部分系统只保留第一项，因此明确提供单张复制与全部保存，不给“复制所有图片”的假承诺。PNG 转换不改尺寸、裁切或美化，不修改已保存原图。
- 剪贴板写入异步完成，大图编码期间读取可能仍是上一段文字或暂存类型；等待写入完成提示后读取真实 PNG 并核验尺寸。
- 新生成结果出现冲突时，嵌套待核实列表沿用了旧结果的关闭状态，导致点“查看核对依据”仍看不到冲突；按冲突内容重置列表的默认展开状态，浏览器覆盖这一原触发链。

## 验证

- 后端全量 496 项、前端 163 项测试，typecheck/build 与 Docker Compose 经典构建。
- 浏览器沿用固定真实参考样本和模拟模型：文案先于图片/设置、手写保护、候选采用、自定义预设、无照片生成、冲突提示与并发保护。
- 实际读取浏览器图片剪贴板，PNG 宽高等于原图自然尺寸；桌面实际 ZIP 下载。手机窄屏截图、底栏复制按钮可见、原图在点击手势内交给模拟 Web Share 接口；无真实手机相册写入或闲鱼粘贴验收。
- 正常流程要求 console/pageerror 零错误；预期并发 400 单独识别。用户数据未修改，未发布或部署。
