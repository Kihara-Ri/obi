# 2026-10-19 · 手机不自动弹键盘；金额清空回到 0、点击覆盖 0

- **作者**：Claude
- **范围**：`web/src/components/ui/Drawer.tsx`、`web/src/forms/fields.tsx`（新增 `AmountInput`）、`SaleForm`、`SaleCostsForm`、`ConfirmForm`（退款）、`record/MoneySection`（额外买入费用）、`ShipForm`（经 `MoneyField`）、`styles/drawer.css`

## 改了什么
- **不自动弹键盘**：触屏（`pointer:coarse`）或宽度 ≤840px 时，抽屉打开聚焦抽屉本身（`tabIndex=-1`，无焦点环）而不是第一个输入框，所有抽屉一致；桌面保持原行为。
- **金额输入**（`AmountInput`）：清空后回到 `0`（费用类 0 是合法值）；值为 0 时聚焦即整体选中，直接输入覆盖，不再出现 `05`、`0.5` 之类；去掉前导零；输入到一半（`1.`）不被当成清空。应用于平台扣费、寄出运费（记录售出 / 修改销售费用）、退款总额、额外买入费用。运费（`MoneyField`）仅有「0 选中」，清空不补 0。

## 出现的问题
- 成交价、买入金额没有设「清空回 0」：成交价为空是「尚未填写」，补成 0 会让误点确认就记成 0 元成交；买入金额选填，空 = 成本未知 = null（红线 3）。
- 第一次批量改 import 时 macOS `sed -i` 语法失败，改用脚本。

## 怎么解决的
手机宽度实测记录售出：打开后焦点在抽屉上；扣费框 0 被选中，输入 5 得 `5`，退格回 `0`，再输 8 得 `8`。类型检查、构建、前端 120 项测试通过。

## 可能带来的新问题
- iOS 真机上数字输入框 `select()` 的表现未实测（桌面 WebKit/Chromium 模拟通过）；若 iOS 不全选，需改用 `type=text`+`inputmode`。
- 触屏判断含「窄窗口桌面」，窄窗口桌面用户打开表单也不再自动聚焦第一个字段。
