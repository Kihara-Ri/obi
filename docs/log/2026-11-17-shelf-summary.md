# 2026-11-17 · 库存页统计卡重排，待确认版本按地区计数

- **作者**：Claude
- **范围**：`web/src/pages/ShelfSummary.tsx` / `ShelfSummary.css`（新）、`web/src/pages/ShelfPage.tsx`、`web/src/pages/PendingReleases.tsx`

## 改了什么
库存页顶部统计卡原来是一行挤着「张数 · 总成本 · N 张待确认版本 › / 已上架」，手机上折成两行、没有主次。改为：总成本大字（下附成本待补），右侧张数 / 已上架，底部一整行「N 张待确认版本 · 去确认 ›」。

## 出现的问题
用户问待确认版本模块是否正常。逻辑本身正常：确认版本或「查不到，标为已处理」后 `app.refresh()`，数字立即变（样例上实测国内 7 → 6、查询页 14 → 13）。但计数用的是全库（国内 + 海外 + 在途 + 售出中），挂在国内卡上读起来像「54 张里有 29 张」。

## 怎么解决的
统计卡只数当前地区；查询页列表按国内、海外、在途、售出中排序，与卡上的数对得上。卡片拆成独立组件，ShelfPage 少了 20 行。

## 可能带来的新问题
线上真实数据需要登录，没能直接核对真实数量；样例数据上验证了计数、点进查询页、标为已处理后数字更新，手机浅色 / 深色与桌面截图无横向溢出。售出中的专辑仍计入待确认（`releasePending` 只排除已售出与回收站），沿用原口径。
