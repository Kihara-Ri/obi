# 2026-10-23 · 扫码打开过渡：等画面稳定，快门式显现

- **作者**：Claude
- **范围**：`web/src/components/BarcodeScanner/BarcodeScanner.tsx`、`BarcodeScanner.css`、`CHANGELOG.md`

## 改了什么
视频不再在 `playing` 事件时淡入，而是等 `settled()`：有首帧、有真实宽高、最近 250ms 无尺寸变化（上限 1.5s）后才显示视频：淡入 0.55s + 从 1.07 倍缩放回原位。取景框改为四个角标（不画整圈边框），出场时从 1.55 倍收拢，识别器就绪时「锁定」微缩一下。用户从几种方案里选了「相机快门式」，最初的 clip-path 展开版已被替换。减少动画偏好下无动画。

## 出现的问题
用户反馈：打开扫码时先出现一个较小的方形相机窗口，然后才扩展到全屏。我无法在真机复现；推测是相机刚启动时先以小尺寸 / 低分辨率出画，随后切到 1920×1080（`playing` 触发时画面尚未稳定），另外选镜头时会连开两次相机流。

## 怎么解决的
把「出画」时机推迟到画面稳定之后，并把显现做成有意设计的动画，启动期中间态藏在暗底后面。Playwright + Chromium 假摄像头逐帧截图验证了顺序：暗底 → 角标收拢 → 画面淡入 → 角标锁定。放弃了只调淡入时间的方案：治标，仍会露出中间态。

## 可能带来的新问题
稳定判定会让画面最多晚出现约 0.25–1.5s；若真机的小窗来源不是视频分辨率变化（比如系统相机预览），这个修法可能不够，需要用户再反馈。未在真机验证。
