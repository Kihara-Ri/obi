# Album Engine 0.2 交付记录

2026-10-16：已完成本轮系统归属重构与本地验证，未提交混合工作目录、创建远端发布或部署真实实例。

## 实现结果

- 收藏展示九种布局统一使用平面封面；打开、换张、重开灯箱均从 2D 开始。只有当前发布实体通过引擎能力检查才显示 3D 切换。点击 3D 才申请感应、加载查看器、Three.js 和 GLB；关闭、切回 2D 或失败会卸载并清理查看器。
- 引擎拥有 schema-v2 `AlbumDocument`、共享 JSON schema/model-set、组件毫米尺寸、父子关系、语义挂载、印刷面、包容关系和来源。宿主直接交付 canonical document 与授权资产解析器，不再往返转换账本记录。
- 模型、装配、贴图处理、生成任务执行、校准、人工素材映射、附件编辑、发布校验与发布决策归 Album Engine。宿主保留副本/交易业务、发行版本确认、鉴权、共用外部客户端、任务租约及 storage.py 原子事务；兼容模块只做窄接口适配。
- npm 查看器/模型与纯标准库 Python runtime 均为 0.2.0，启动和构建核对版本、schema、model-set 与 rig。Docker 和裸机应用包均包含独立运行所需内容，不依赖相邻引擎源码目录。
- 全部包装与附件建模使用 Blender。保留原 21 个库模型，新增 OBI、歌词本、内袋三个 GLB；运行时克隆模板、设置作者制作的形状键、材质和装配变换，不另造附件网格。
- OBI 具有连续 front–spine–back 印刷与反面；纸宽、纸高、盒深分别通过 Blender 形状键调整。歌词本置于所属页面的固定载体上方，与 CD 分层。内袋与 CD 共心、保留纸层与三条封边；内侧开口不镜像图像。
- 内袋及其 CD 都先沿各自袋口平面退出，尾缘离开后才抬升；歌词本覆盖 CD 时，先移开歌词本才能取碟。关盒先收回 CD，再收纸件。书脊校准与作者骨架共用纸件净空下限，图像估计不能越过这一约束。

## 当前支持范围

19 种既有基础包装定义及三组代表实体通过统一协议回归。当前完整 3D 装配只支持所选 Blender 模板尺寸；不同的实测尺寸保留原资料并使用 2D，待引擎提供对应模型与完整净空验证后开放。不会将 120 mm CD 整体拉伸来适配盒体。

旧实体有含糊附件归属时维持 2D；普通校准、成本/笔记修改和恢复不凭空补出挂载关系，也不自动重跑生成。未来优化入口在引擎内。
