# Installable Album Engine and durable user entities

> Agent workers use the already-read subagent-driven-development workflow for independent engine/backend/frontend work. Preserve existing work and untracked files. No commit, push or deploy.

**Goal:** Settings installs/uninstalls an actual packaged optional Album Engine; core ledger + 2D work with its executable assets absent, while user entities and their model/texture/presentation assets survive uninstall, restart, backup/restore and reinstall.

**Architecture:** Engine project builds a self-contained browser/runtime/model archive and a separate generated persistence-data codec. Host retains only plugin lifecycle, private asset access, ledger persistence and thin UI bridges. Package installation lives below the user's data/plugins; opaque entity documents/profile and pinned asset manifests live in SQLite via Store, binary images/GLBs remain in user data directories. Engine owns all 3D implementation and future package production.

**Spec:** Current user's explicit request overrides the old no-dynamic-plugin guideline. Uninstall removes executable browser/runtime/model plugin installation, not user entity data. New generation needs installed engine; old metadata/export/backup remain readable without it. No remote marketplace or arbitrary executable upload in this first version; install from the shipped, hashed official local package catalog. New empty instances default uninstalled; existing preview will be explicitly installed for final inspection.

## Interfaces

- Engine archive: `album-engine-plugin-<version>.zip` containing `manifest.json` (`id:'album-engine'`, `pluginProtocol:1`, version/modelSet/schemaVersion/rigVersion, `browserEntry:'browser/plugin.js'`, `style:'browser/style.css'`, `runtime:'runtime/album_engine'`, `models:'models/packaging'`, SHA-256 per archive file). Plugin files have no user data or absolute paths.
- Host API `GET /api/plugins/album-engine`: `{installed,available,version,availableVersion,revision,entryUrl,styleUrl,modelBaseUrl,busy,error}`; `POST /api/plugins/album-engine/install` / `uninstall` with optional expectedRevision. GET assets prefix `/api/plugins/album-engine/assets/` serves only active plugin files under authentication. Install/uninstall apply CSRF and write authorization.
- Runtime PluginManager `status()`, `install(expected_revision=None)`, `uninstall(expected_revision=None)`, `start()`, `stop()`, `service()`; Services.plugins injected, Services.twins remains a stable forwarding facade that denies generation if missing. No import failure can prevent ledger startup. Busy queued/running generation rejects uninstall; no implicit cancellation or task rewrite.
- Browser entry exports `manifest`, `inspectAlbum`, `requestAlbumOrientationPermission`, `editionMaterialSources`, calibration helpers, and `mount(kind,element,props):Promise<dispose>` for `viewer`, `guided-editor`, `accessories-editor`, `disc-calibration-editor`. Each mount owns a separate engine React root; no React hook shared across roots. Browser bundle is self-contained, viewer/Three lazy, styles external. No engine runtime static imports in host entry.
- Shared data codec is generated in engine, exported to host `vendor/album_data` (stdlib persistence only) and `web/src/vendor/album-data` (pure metadata helpers). It may read/validate entity/task/packaging wire data for core backups, but contains no rendering, generation, network worker, input, motion or model implementation. Host never hand-edits these exports.
- User data model snapshots: before publication/uninstall, pin GLB files in a content-addressed user asset directory; Store records version/hash/file map per job. Reinstall resolves the same pinned model set. Hashes and document/presentation data roundtrip in normal backups; complete data backups include binary assets. No directory deletion outside plugin installation on uninstall.

## Acceptance

No removal/modification of records, sales, shipments, published entity document, pinned GLB/texture hashes or saved camera profile by plugin lifecycle. Core business mutations still retain appearance invalidation rules. Missing costs remain null. Uninstalled client issues no Album Engine browser/GLB request and shows ordinary covers. Preserve the existing independent MetalBackCanvas 2D flip-card decoration; its lazy Three.js is outside the 3D album plugin. Install restores original model and content interaction without regeneration. Incompatible stored documents stay preserved in 2D. Package source must live in engine, not host 3D implementations. Deployment requires no Blender/pip runtime.
