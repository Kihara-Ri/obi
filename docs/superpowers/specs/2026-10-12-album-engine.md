# 唱片实体引擎第一阶段

用户已确认：建立两个仓库，模型、材质、实体动作和镜头由独立引擎共同维护；先抽完整查看器与模型工具链，建立独立 Studio，再原样接回碟渡。生成算法在后续阶段抽离。

## 接口与归属

- 碟渡保留收藏、交易、九种浏览布局、灯箱导航/历史/缩略图过渡、发行版确认、生成任务、资产授权及 storage.py 发布事务。
- album-engine 包含现有 WebGL 查看器、CSS 回退、感应与清理、全部 21 个 GLB、Blender 源、投影/校准/材质/动作/镜头及其测试。
- 对外 `AlbumEntity` 是版本为 1 的包装、印刷面素材引用、投影和校准描述，不包含 AlbumRecord、照片序号、金额、交易状态或任务状态。
- `AlbumViewer` 接收实体、素材解析函数、模型资源配置、感应授权 promise 和关闭回调。包装与唱片的连续动作由引擎维护。
- 碟渡适配层保留旧包装文字解析及素材 URL 拼接。包装规则可经轻量入口复用，不因此加载 Three.js。
- 模型结构协议固定为 rigVersion 1：现有单位、轴心、印刷面材质与 GLB extras 不变。引擎及兼容 GLB 一起版本化发布。
- 首版使用一个 npm 包及独立 Studio。可复现 tarball 存入碟渡 web/vendor，npm lock 固定它，避免要求运行者拥有第二个源码仓库。构建时复制包内模型到既有同源 static/models/packaging，文件名保持稳定。
- Studio 使用固定样本库导出的合成描述与纹理，不连接碟渡 API，不复制个人数据。合成场景仍由 tools/seed_samples.py 维护。

## 验收

旧样本包装、贴图、开合、抽盘、运镜及 CSS 回退不变；刷新保留动作状态；灯箱关闭/历史返回恢复浏览位置；关闭清理监听与 WebGL。Studio 脱离碟渡后端工作，能切换既有三种合成实体并操作模型。安装 tarball 后完成前后端检查、浏览器关键流程与 Docker 构建；主工作目录未提交修改得到保留。
