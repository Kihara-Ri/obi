# 3D Album Engine 完整归属与 2D 默认展示

日期：2026-10-15。状态：用户已确认，实施中。覆盖此前“生成算法后续抽离”的分阶段范围；现有数据与未提交工作保留。

## 用户已明确的结果

1. 交易管理的收藏展示统一从 2D 封面开始，包括点开后的灯箱。
2. 只有引擎明确支持的实体可以由用户切换到 3D；有包装字段、共享 GLB 或历史生成成功记录均不能单独作为支持依据。
3. 侧标、歌词本、内袋、CD 等必须具有统一的数据结构、尺寸与装配约束，不能靠各处写偏移凑位置。
4. 所有 3D 系统归独立 Album Engine：模型、素材处理、生成、校准、发布、查看器、组件交互、镜头与资源清理。用户已明确包含生成与发布管线。
5. 后续关于 3D 模型的优化直接在引擎仓库实施；交易系统只接入引擎的版本化产物。

## 已核对的当前实现

- 宿主接入 `@diedu/album-engine` 0.1.10，本地独立仓库为相邻的 `album-engine`。两个工作区都有尚未提交的相关改动，实施时在其基础上衔接，不能回退或覆盖。
- `GalleryFocus` 用 `twinViewerRecord` 的非空结果直接选择 `AlbumModel`，没有 2D / 3D 显式切换。`GalleryPage` 在打开灯箱时就请求方向感应。
- `GalleryCase` 仍根据包装种类在宿主绘制背面、厚度面；宿主展示 CSS 还覆盖查看器内部类名。
- 当前链路为“已发布 entity → 临时 AlbumRecord.model* 字段 → toAlbumEntity → 引擎 ViewerInput”，中间往返容易丢失实体语义。
- `AlbumAccessory` 只有 id、kind、asset、region 和来源，没有尺寸、所属组件、挂载槽位、包容关系和有效性约束。
- `album-scene.ts` 按 `Panel_Left` / `Lid_Hinge_Y` / `Pocket_1` 等名称选择附件父节点；`album-accessories.ts` 的歌词册仍使用固定的 112×116×2 mm 和固定 home / extract。已有侧标、内袋 GLB 测量改动不能代替全部组件的统一协议。
- 宿主 `DiscCalibrationEditor` 仍实现校准交互与预览；`server/twin_sources.py`、`twin_surfaces.py`、`twin_assembly.py`、`twin_guided.py` 以及随包 skill 仍含生成逻辑。`twins.py` 同时混有宿主任务协议与实体校验。

以上是源码证据；尚未将本次截图的每个画面与运行中数据逐项复现，不把已有修复记录当作本次视觉验收结果。

## 一、两个系统的职责

| 交易管理保留 | Album Engine 统一管理 |
| --- | --- |
| 副本、收藏、采购、交易和艺人资料 | 可序列化实体协议、兼容转换、能力判断 |
| 收藏范围、分组、搜索、排序、九种布局的封面排列与漫游 | 包装、托盘、口袋、侧标、歌词本、内袋、CD 的模型与装配 |
| 2D 灯箱外壳、上一张/下一张、浏览器历史和返回位置 | 3D 查看器、旋转、开合、取放依赖、镜头、感应及资源生命周期 |
| 发行版本的明确人工确认和副本关联 | 已确认版本范围内的素材规划、图像处理、几何构建和质量校验 |
| 网络配置、共用 MusicBrainz 节流及凭证保管 | 素材和组件来源的使用规则、生成阶段与可恢复执行逻辑 |
| `storage.py` 的事务、审计、并发令牌、模块权限、备份与恢复 | 发布包构建、包内完整性校验、版本兼容规则和发布决策 |
| 经注入适配器执行文件与数据库持久化、同源鉴权取图 | 独立 Studio、合成夹具、组件校准编辑器和模型回归 |

“引擎管理发布”指引擎构建并验证不可变发布包，决定何时满足发布条件，再调用持久化接口。数据库写入仍只通过宿主 `storage.py` 的事务执行；引擎不直接连接账本数据库，不拥有金额或交易状态。宿主不再自行决定组件几何、素材拼装或生成是否合格。

## 二、2D 为默认，3D 是按张显式切换

### 展示行为

- 九种布局继续保留现有排列、拖动、漫游、选择和返回位置；专辑本体统一为平面封面，不再由 `GalleryCase` 合成包装前后面和厚度。布局轨道的空间排列不等于加载 3D 实体。
- 每次打开灯箱、切换上一张/下一张、关闭后重开，都先显示 2D。3D 开启状态不持久化为下次启动状态。
- 2D 封面依次使用已有封面、引擎已发布的平面预览；都没有则保留“暂无封面”。不在打开页面时自动抓图或生成，不把未裁正的整张展开照当作封面。预览可以是已经裁正的图片，也可以是已发布的原图与裁剪/校准描述；后一种由引擎独立轻量 2D 入口通过浏览器 Canvas 投影，不加载 Three.js，也不要求 Python 后端安装图像解码库。
- 引擎能力检查通过时，灯箱出现紧凑的 `2D / 3D` 分段切换，默认 2D；不支持时只显示 2D。展示中不加入生成入口或任务状态。
- 用户点击 3D 的同一手势内请求方向感应，再按需导入查看器和 Three.js。打开 2D 灯箱不申请感应，不下载 GLB，不创建 WebGL。
- 切回 2D、换专辑、关闭灯箱都卸载查看器，取消动画和异步加载，释放 GPU、监听器与指针捕获。2D 封面与所在布局位置不改变。
- 3D 运行时发生模型缺失、几何验证失败、WebGL 不可用或上下文丢失时，返回原 2D，显示简短的“3D 暂不可用”；当前实体在本次灯箱内可显式重试。不得自动展示畸形、部分组装或冒充完整实体的 CSS 模型。独立 CSS 查看器可以留给 Studio / 兼容测试使用。
- 2D 保留背景点击、Esc、浏览器返回、缩略图缩放和左右切换。3D 内部的背景命中、拖动误点和键盘处理由引擎负责，宿主只响应关闭/不可用事件。

### 轻量接口

新增独立入口 `@diedu/album-engine/capabilities`，只依赖实体协议与随包能力清单，不导入 React、Three.js 或查看器。

```ts
type AlbumCapability =
  | {supported: true; entity: AlbumEntityV2; modelSet: string}
  | {supported: false; reason: 'schema' | 'model' | 'assembly' | 'assets'};

inspectAlbum(entity: unknown, modelSet: EngineModelSet): AlbumCapability;
```

输入没有任务状态。宿主先保证实体是当前有效的已发布版本，再交引擎检查；引擎检查协议、模型版本、全部组件/挂载槽位、尺寸约束及必需资产声明。实际文件加载仍可能失败，由查看器的 `onUnavailable` 返回 2D。不能用 `status === succeeded` 代替能力检查。

## 三、实体协议与组件装配

### 版本和物理坐标

- 新完整协议为 `schemaVersion: 2`。现有 v1 只读兼容，不修改历史记录或重新启动任务。
- 发布文档中的尺寸统一为毫米、角度为弧度；几何内部统一为米。转换只发生在引擎一个入口，不允许宿主缩放附件或重复应用外壳缩放。
- 序列化尺寸必须记录 `measured` 或 `template` 依据及其来源。未填写实测尺寸时使用引擎模板值，不把比例估算写成实测值。
- 坐标、朝向、挂载变换和抽出路径属于引擎 rig/socket 定义；宿主输入不接受用来修画面的任意 `position` / `rotation` / `scale`。

### 核心数据

```ts
interface AlbumEntityV2 {
  schemaVersion: 2;
  key: string;
  title: string;
  modelSet: string;
  assembly: {root: string; components: AlbumComponent[]};
  assets: Record<string, EngineAsset>;
  preview?: EngineSurface; // 已裁正图片，或供引擎轻量 2D 投影的资源与校准
}

interface AlbumComponent {
  id: string;
  kind: 'package' | 'tray' | 'pocket' | 'disc' | 'obi' | 'booklet' | 'inner-sleeve';
  definition: string; // 引擎随包注册的模型/参数化组件定义
  parent: string | null;
  mount: string | null; // 在 parent 定义中声明的语义槽位
  dimensions: {
    width: number; height: number; depth: number;
    basis: 'measured' | 'template'; source?: string;
  };
  surfaces: Record<string, EngineSurface>;
  contains?: string[];
}
```

这是接口方向，精确 TypeScript 联合类型与生成的 JSON Schema 由实施者按各组件收窄；不能让所有 kind 共享一张无限可选字段表。`EngineSurface` 保留四点裁剪、曲面映射、盘面校准；`EngineAsset` 保留来源类别、发行版与素材归属。资产使用不透明 ID，不包含账本 ID、照片序号、金额、交易状态或任务 API URL。宿主通过 `resolveAsset` 提供同源授权 URL。

结构的唯一来源在引擎 `schema/album-entity-v2.json`；TypeScript 声明与 Python 校验入口由同一协议产生，业务校验规则也由引擎维护。宿主的手写类型和 `clean_entity` 不再复制这套规则。

### 组件归属与约束

- ID 唯一，parent 与 contains 引用存在，组件图无环，根唯一。单个 CD 只能位于一个实际容器中，不能同时占据两个口袋或内袋。
- 模板显式声明语义槽位、局部坐标、可用容积、开口方向、允许的 kind、默认尺寸与抽出方向。不能通过查找第一个 `Pocket_1` 或同名节点猜归属。
- 导出 GLB 的节点名称可作为引擎内部定位实现；对实体公开的装配约束只引用版本化语义槽位。变更坐标或槽位协议必须升级 rig 契约，不能静默替换。
- OBI 的高度受印刷外壳边界约束，折叠宽度和厚度匹配本外壳；不取包括隐藏托盘、CD、其他附件在内的整体包围盒充当纸板轮廓。
- 歌词本明确放入哪个封面内槽/口袋，宽高厚度不得超出该槽可用容积；不同位置不共用固定偏移。若尚不支持多页翻动，仍按整体本册建模，不能虚构册页。
- 内袋必须包住其指定 CD：内部宽高大于盘径加间隙，内部厚度大于盘厚，外部尺寸小于口袋可用空间；只沿该袋声明的开口取盘。
- 在引擎中一次计算装配结果，模型、raycast、遮挡、动作轨迹与镜头均使用该结果，不能分别推算不同位置。
- 状态依赖集中维护：OBI 撤离后开合；内部纸件可达后抽出；内袋抽出到许可范围后取 CD；关闭前先收 CD 和纸件；反向操作从当前位置连续接管。
- 不可满足的尺寸/槽位/关系在生成或发布前拒绝。运行时只读历史兼容失败时返回不支持，不能悄悄跳过附件并声称完整支持。

不引入通用物理仿真或动态插件框架。当前需要的是可检验的刚体/纸件几何与运动约束。

### 本轮最低支持清单

不能通过把全部旧模型都标为不支持来完成迁移。以下为根据现有能力与用户截图确定的实施下限：

- 保留当前 21 个库模型对应的全部既有基础包装与载体组合：六类包装、Jewel Case 厚薄/多碟、Mini LP、两至四折、内外开口以及既有 Slipcase 组合。`neutral` 仍是未知结构示意，不计为已支持的真实 3D 实体。
- 用户截图涉及的二折 Gatefold 必须完整支持 OBI、歌词本、内袋和双 CD 的组合，覆盖 125 / 135 mm 纸板、内外开口及左右归属；这组不能以“协议升级”或“暂不支持”降级代替修复。
- 其余包装的附件仅在对应语义槽位和容量经过固定样本验证后宣称支持；缺少实物结构证据的组合明确不支持，不能沿用旧的任意挂载。基础包装的兼容能力与附件完整装配能力分别验证，但一次实体检查必须对其全部实际组件给出整体结果。
- 各基础模型至少有一个由固定样本源生成的装配/资源回归，交互浏览器重点覆盖既有三个代表样本和上述完整 Gatefold 组合。不能只对一个正常外壳验证后声称全部迁移。

本轮不扩展到任意多页翻书、任意盒中盒或所有现实发行版；新增型号继续在引擎建立定义与样本。

## 四、生成、素材与发布也归引擎

### 分发形式

沿用现有 TypeScript / Three.js 查看器，在引擎仓库新增纯 Python 标准库运行部分 `python/album_engine/`，与查看器和模型同一版本发布。宿主服务端不增加 pip / Node / Blender 运行依赖。

引擎发布两份匹配产物：npm tarball（查看器、协议、CSS、模型、能力清单）与 Python runtime 归档（生成执行器、实体校验、素材规则、随包 skill 与运行协议）。宿主把 runtime 的发布文件安装到 `vendor/album_engine/` 并跟踪，文件标为引擎产物、禁止手改。Docker 和裸机打包直接包含它，不依赖相邻源码仓库。两端版本/协议兼容性在构建和启动时检查。

这是实施者提出的分发方案：用第一方 vendored 标准库模块保持现有部署约束，避免另起必须运行的模型服务。

### 运行接口

引擎接收已确认发行版、只读素材清单、模型调用能力和持久化能力，负责 PLAN / BUILD / 校准 / 约束校验 / 发布决策。宿主注入：

- 素材读取/限额下载与共用 MusicBrainz 客户端；URL 与图集仍需确认和授权。
- 已有视觉模型调用能力，密钥不进入实体或返回客户端。
- 命令去重、版本比较更新、工作租约、心跳、文件暂存和发布事务接口；底层实现保持在 `storage.py`。

引擎不接受任意宿主对象或 Store 实例。适配器只实现窄接口，不包含“如果 gatefold 则放左边”之类规则。

### 发布顺序

1. 宿主确认副本与发行版，事务建立/复用任务并冻结输入与来源。
2. 引擎取得有效租约，读取已授权素材；处理期间没有数据库写锁跨越网络调用。
3. 引擎输出独立暂存发布包：entity v2、可显示的 2D 预览描述、全部资源、组件关系、来源和版本清单。涉及图像解码/栅格投影的预览由引擎浏览器模块完成，标准库服务端只保存资源与验证描述；不增加 Pillow 等运行依赖。
4. 引擎校验结构、引用、图像边界、尺寸约束和当前模型能力；失败转为需补充/失败状态，不发布半成品。
5. 引擎请求发布；`storage.py` 在同一事务内核对租约/seq、当前输入版本、取消/过期/已有结果，切换到完整包引用并写审计。
6. 读回显示为可用；迟到结果、旧任务或重复确认不能覆盖新发布版本。断线后通过已有任务标识读回，不重新生成。

原始照片、购买信息和包装记录不被发布结果覆盖。取消、断线重试、恢复后不重放、照片/包装改变后失效、笔记/金额改变不失效等原契约保留。存储迁移仅处理必要的结构兼容，不扫描或改写真实 `data/`。

校准编辑器的交互、绘制、算法与样式移至引擎独立导出。宿主在“编辑专辑”中挂载，保存回调调用宿主鉴权接口；展示灯箱不再放“校准盘面”入口。

## 五、兼容与切换

- 历史发布 v1 保留原包与来源。引擎提供显式的只读 `normalizeLegacyEntity`；可确定的外壳、盘片关系按当时模板编译成新内部结构。
- 旧附件只有种类/图片且归属无法唯一确定时，返回不支持，维持 2D；在编辑中显式重新生成或补充信息。不得因为降级自动删附件、改数据或重跑模型。
- 旧接口 URL 可保留，由 `server/album_engine_adapter.py` 转成引擎命令；不保留两套生成实现。`twins.py` 只保留宿主任务与记录指纹等职责，实体规则委托引擎。
- 现有任务格式只做必要的读取兼容；新执行状态由引擎管理，宿主存储 opaque 状态与少量用于鉴权/并发的索引字段。运行中的旧任务先按已有安全边界停止/标记中断，不把旧 phase 强行当作新 phase 自动恢复。
- 同一实体不变的刷新不能重置已打开的 3D 姿态；实体、资源或发布版本改变则创建新查看器。

## 七、样本和验收

## 设计中由实施者作出的选择

- 九种布局保留，平面化的是专辑本体；显式 3D 切换放在灯箱内，逐张重置为 2D。
- 失败回到真正的 2D；CSS 3D 回退仅保留为引擎可选能力，不再作为宿主默认降级。
- schema v2 承载明确组件关系；v1 只读兼容，不能确定的装配降级。
- 纯 Python 标准库 runtime 与 npm 包由同一引擎版本发布，宿主 vendoring，维持现有一键部署。
- 引擎拥有发布决策与包校验；宿主通过 storage.py 提供最终原子提交和授权。
- 基础包装不缩减现有支持，优先完整修复截图所涉及的 Gatefold 附件组合；其他真实结构不足的附件组合按引擎能力判断。

独立构建审阅提出“最低支持清单不明确，可能退化为全部降级”。上面的支持下限已据现有模型库与截图补齐，不需要再由实施者猜测。
