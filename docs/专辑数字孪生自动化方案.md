# 专辑数字孪生自动化方案

网站已接入**编辑区手动触发的条码核对与 skill agent 生成管线**。用户从已保存的实物照片读取清晰条码；没有可读条码时输入号码或补拍。按条码精确查询 CD 发行版后，返回版本资料、曲目和图集供用户确认，确认前不会开始生成。无需还原要求或发行版链接。展示页只呈现封面/已发布实体和标题。

`server/skills/album-digital-twin/` 是随应用打包的技能源。2026-10-11 核对 King Crimson《Islands》条码 `4988013047105` 匹配 [日本 2000-03-01、PCCY-01424 的 1CD 版本](https://musicbrainz.org/release/e618bce6-8e08-4628-9574-2d8f53b20db7)，6 首曲目。该 release 的 Discogs 关系指向 [2485482 元数据](https://api.discogs.com/releases/2485482)，完整条码和编号一致，说明为 gatefold vinyl replica sleeve，另含英文 12 页、日本文 8 页及 OBI。该资料支持对折纸套参考结构，不能证明当前副本尺寸或磨损。

同版 CAA 有 10 张原图：`10468808112` 为 3244×1592 星云正背展开图，与 Discogs 的 598×296 展开图印刷和折线相符；`10468812400` 的歌词/拼贴双面及宽折脊与 Discogs 独立两面和纸边对应，可作为包装内面参考。两图虽标 `Booklet`，不能只凭标签排除；`10468809617` 的可见订钉中页属于册页，不能用于包装书脊。每个面的最终采用仍须实际图案及结构核对。Discogs 图集实际长边最多约 600 px，优先同版 CAA 较大图；条码匹配与成功下载均不等于素材完整。

## 采用哪条路线

建议采用**参数化包装模板 + 精确发行版本识别 + 实物采集**。常见包装复用 Blender 模板，自动填写结构、尺寸、材质和各面贴图，不必逐张重做模型。印刷图与开合轴、纸袋、托盘分别处理，方便保持结构正确。

不以单封面生成未知背面。网上同版图能补通用印刷，但这张副本的折损、旧化和附件必须从实物采集。没有测量的模型仍是参考比例。

也不将整件摄影测量扫描作为主路径。Apple 指出透明、高反光、很薄的结构和拍摄时变形的物体容易导致低质量或失败；CD、透明盒和可展开纸套正涉及这些条件。因此模板路线更适合这里的可开合包装，这是依据采集限制作出的工程选择。[Apple 采集指南](https://developer.apple.com/documentation/realitykit/capturing-photographs-for-realitykit-object-capture)

## 最少采集什么

- 正面、背面、完整展开内页、书脊及袋口/连接处；每张取出 CD 的盘面。清晰的一张图可以覆盖多个面。
- 清晰条码、唱片编号；版本仍冲突时补内圈刻码。不凭标题决定包装。
- 要求实物尺寸时，提供宽、高、厚度，或同平面的尺子与厚度侧照；避免强反光和硬阴影。

视觉模型判断结构、碟数、开口方向、照片角色及四角/连续边界行；只对低置信度、互相矛盾或校准失败的项要求确认或补拍。没有拍到的面保留“缺失”，不复制封面填满。Codex 可执行现有 skill 的标准库脚本做可重复边界校准；当前没有供用户手拖四点或折线的独立界面。

数字实体入口先用条码精确查询，再由用户核对艺人、碟数、曲目和可见结构；无条码时提示补充，不按名称猜发行版。MusicBrainz 的其他录入资料补全仍可使用 `barcode`、`catno` 搜索。确认具体 release 后，CAA 可列出原图、缩略图、角色与审核状态，角色包含 Back、Panel、Booklet、Medium、Spine。但图集可能不完整，角色也不等于已裁好的一张模型贴图。[版本查询](https://musicbrainz.org/doc/MusicBrainz_API/Search)、[CAA API](https://musicbrainz.org/doc/Cover_Art_Archive/API)、[图片角色](https://musicbrainz.org/doc/Cover_Art/Types)

## 现有基础与缺口

数字实体服务直接使用已经在编辑页面确认并保存的 MusicBrainz Release ID 获取同版图集；旧照片条码 OCR、生成阶段二次搜索和二次确认已删除。确认后的素材规划与校准复用 `VisionService.agent_json()` 配置及并行槽位，返回结构化包装、逐面坐标与可选校准，校验后发布。Discogs 补证限于已确认 MB release 的精确关系并复核条码、编号和介质，网络失败保留缺口。普通录入识别与批量草稿仍使用原合同，不会因新增记录自动调用生成 agent。

`PackagingEditor.tsx` 保留副本的人工结构和照片绑定；生成不会改写它们。`core/digital-twins.ts` 将已发布实体映射为仅供查看的模型参数，`core/album-entity.ts` 再转换为纯 `AlbumEntity` 与 `surface:<role>` 素材引用，宿主负责受保护 URL 解析。`AlbumModel.tsx` / `CSSAlbumModel.tsx` 是独立 `@diedu/album-engine` 查看器的适配器；共享 GLB 选择、投影与渲染分别位于 `album-engine` 仓库的 `src/core/album-model-assets.ts`、投影模块与 `src/core/album-scene.ts`。Blender 模板源在该仓库的 `tools/model-library/`。多面素材由碟渡的独立生成任务获取，普通 `covers.py` 仍主要补正面。

碟渡通过 `web/vendor/` 中固定版本的自包含 tarball 引入引擎，构建时复制模型；查看器与模型工具链的拆分保留原展示行为，条码核对、生成算法、任务状态、资产授权及发布事务继续在碟渡。版本更新与独立 Studio 的流程见[唱片实体引擎](模块扩展指南.md#唱片实体引擎与更新)。

实体的 `surfaces[role].warpRows` 保存 2–17 行原图归一化左右边界，用连续条带代替仅四角映射；`calibration.spine` 独立保存窄脊/封板宽度比及真实来源。比例限 0.001–0.2，标为 `image-estimate`；可选 3–17 点起伏限 ±0.15 mm，仅表示明确提供的近似。原图、人工包装及实测尺寸不变，印刷明暗不生成高度。模型保留 120 mm CD 所需空间，纸纹在缩小/斜视时过滤减弱。

## 在 Codex 中执行现有 skill

使用 `$album-digital-twin`，先运行条码候选检索，等用户确认后获取该版原图；`scripts/calibrate_spine.py` 输入原图宽高和已确认的正、背、脊边界，输出可合并到 BUILD 的 JSON。输入与坐标规范见 [书脊校准协议](../server/skills/album-digital-twin/references/spine-calibration.md)。产物只写新的工作目录；脚本执行与应用真实视觉模型生成分别记录，JSON 经应用原有任务校验发布后才进入展示。

分辨率也有限制：`web/src/core/photos.ts` 上传压成长边 1600 的 JPEG；`album-engine` 仓库的 `src/core/album-scene.ts` 将 GPU 贴图限制为长边 1024（舞台宽度小于 600）或 1536。要放大检查小字、纸纹，需保留高分辨率原件并另做预览；当前不能称保留相机原始像素。

## 三阶段落地

1. **自动建草稿**：把识别结果接到 `packaging.photos/photoRegions`，加入补拍与校准；证据充分的普通模板自动生成，人工已确认字段受保护。
2. **按版补图与批量保存**：接通已确认 release 的多面图集，扩展现有导入草稿；每面记录本副本照片/同版参考、来源、确认状态和缺失原因，全部写入经 `storage.py`。
3. **提高实物精度**：保留高分辨率原件，加入测量与特殊结构模板；检查接缝、穿模和开合中间态，再做手机实机质量验收。

服务端继续使用标准库调用已配置模型；Blender 留在模板制作工具链。目标是资料充分时自动复现、资料不足时明确指出缺口。
