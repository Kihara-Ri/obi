# 汇率模块契约

决策见 D-043（[决策记录](DECISIONS.md)）。金额为服务端 Decimal，接口数值为字符串，每 100 JPY 兑 CNY；仅采用 Frankfurter v1 的 ECB 口径，不混入其他来源。

## 三个边界

| 层 | 接口 | 保证 |
|---|---|---|
| 报价缓存 | `RateService.quote / peek` | 只读；不等待外网请求 |
| 显式准备 | `resolve / warm`、`POST /api/rates/prepare` | 在全局写锁、业务事务外联网；每次准备接口至多一个 60 日窗口 |
| 财务写入 | `Store.prepare_financial` + prepared command | 先准备，再核验快照及报价；锁内仅 Decimal 运算与事务，无联网 |

`rates.py` 统一有效性，`rate_cache.py` 管 SQLite 缓存和覆盖，`rate_provider.py` 管有界请求与数据校验，`financial_rates.py` 管财务准备与提交校验。根模块不依赖 server。

## 有效报价

返回 requestedDate、quoteDate、rate、source、status、checkedAt、provisional；临时覆盖还记 checkedOn。未来日期为 future/null，绝不自动正式折算。历史精确报价可复用；非精确报价必须已经成功覆盖查询目标日期，并且回退不超过 14 天，不能用“缓存里恰好有更早值”代替核对。

最近两天与当天的报价保持临时状态，300 秒后允许重新确认；跨午夜需重查，避免欧洲发布时间边界下把尚未完整的结果永久冻结。成功核对后的较早历史覆盖可持久复用。空结果短暂记为不可用，供应商错误触发跨日期 300 秒冷却；未缓存请求不阻塞已有有效缓存的读取。

状态缓存键包括报价内容版本、日期、到期集合与冷却状态，报价过期或更新都使旧状态失效。

## 账本与界面

`Store.state()` 和 CSV 只读同一份有效报价快照，金额和报价说明来自同一版本；未知成本为 null。人民币、原价未知或已填实际人民币支出的采购记录不准备汇率。state 提供 neededDates，客户端先显示账本，再独立准备报价并刷新。准备任务单一并发、分窗口推进、无进展暂停；传输失败即使后续 state 是 304，也保留有界重试机会。

专辑资料 metadata 保存继续与汇率隔离。前端共用 useRate：按币种及需要启用，切日期立即移除旧值，取消旧请求，显示实际报价日期；失败保留输入。

## 入账依据

日元包裹或销售保存 rateQuote。包裹的原金额、币种或日元发货日期改变时重算人民币总额和每张分摊；仅增减成员时沿用原总额。销售费用修改沿用已记录的同一售出日折算依据，旧单据缺依据才重新准备。准备后若单据并发变化、报价更新或过期则拒绝保存，不在锁内重新联网。

已存在的单据不批量回填或重算；旧报价缓存表兼容，只新增缓存覆盖表，不变更账本 schema。采购页面的 rateQuote 是派生只读字段，不接收表单伪造。

## 本机模式

查询仍在 net Worker，账本仍在 main Worker，二者不共享 IDBFS 目录。net 在向页面回复前，经本次启动 session 和请求 ID，把结构化报价交给 main 校验；main 返回自己的规范结果，较旧回执不覆盖较新缓存。同步有有限超时，错误可重试。

ACK 仅保证 main 当前会话 SQLite 已接收。公开汇率缓存可丢失并重取，不据此承诺浏览器断电持久化，也不改造历史财务写入协议。此适配只有 Worker 内部方法，无接受客户端汇率的服务器入账接口。`POST /api/rates/prepare` 属于缓存查询，不当成财务写请求处理。

## 验证与发布

离线测试与浏览器验收复用固定样本；`seed_rate_review()` 仅调整现有 Dookie 副本的虚构日期以制造缺缓存场景，不新增副本/照片。普通素材仍由固定真实样本包提供。

新增根模块需同步补丁包白名单；本次已同步新版 `tools/update_release.py`。已安装旧版更新器的白名单不认识新文件，正式自动更新发布前需先安排兼容白名单的过渡更新，或经已有服务器发布入口更新，不能以新版自测通过宣称旧更新器可直接接收新包。
