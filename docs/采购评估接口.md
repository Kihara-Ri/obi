# 采购评估接口

> 状态：生效中（2026-11-24 实现）。决策见 D-049。实现：`server/insight_api.py`（路由与校验）、`server/insight_model.py`（成本模型、匹配与估算）、`server/insight_data.py`（账本样本）、`server/insight_stats.py`（加权统计与区间）。场景串讲见[接口场景指南](接口场景指南.md#场景三采购时挑出值得买的)。

Agent 在唱片网站浏览商品时，可以用本接口拿你自己的买卖证据判断哪张值得买：是否已经有、你买这一版通常花多少、卖出去实收多少、多久卖掉，以及按你的成本口径估算候选的落地成本与预计利润。外部行情、排序和推荐由 Agent 完成；Obi 不抓取网站、不保存候选、不下单。

## 边界

- **只读**。不创建、不修改任何账本数据，也不保存 Agent 提交的候选。
- **独立授权**。返回金额，所以不复用[已购唱片查询](已购唱片查询接口.md)的令牌：那枚令牌承诺不返回金额，不扩大它的范围。
- **只返回汇总**。不返回单条账本记录、副本 `id`、买入店铺、订单号、收货地址、备注和照片。只有 1 条样本时给金额区间，不给精确值（见「小样本」）。
- **口径与账本一致**。落地成本、净收入、利润沿用 Obi 现有计算：成本 = 买入金额按买入日汇率折人民币（或实际支出）+ 该副本已分摊的整批费用和国际运费；净收入 = 成交价 − 平台扣费 − 寄出运费 − 退款与退货运费。
- 只在服务器版提供，浏览器与安卓本机模式没有。

## 开通和撤销

本接口需要 `insight:read` 权限，按[对外令牌](对外令牌.md)给「采购 Agent」这个调用方签发（已包含是否已有的判断，不需要另配 `collection:read`）：

```sh
docker compose exec app python3 -m server.client_admin add 采购Agent --scope insight:read
```

令牌只打印这一次，立即生效；`revoke 采购Agent` 立即撤销。本接口没有单独的令牌文件。不要求开启任何模块；账本里没有买入或销售数据时，各项统计为空。

## 统计口径

- **近期优先**：每条买卖样本按发生日期指数衰减加权，半衰期默认 180 天（半年前的一笔算半票，一年前算 1/4）。只统计最近 36 个月，更早的权重已不到 2%。半衰期可用 `halfLifeDays=60..720` 调整，`profile` 和 `evaluate` 都接受。
- **加权中位数**：所有 `…Median` 都是加权中位数；`costRange` 是加权后的 10%–90% 分位。每组统计都带 `n`（样本条数）和 `nEff`（有效样本数，Σw² 意义上的 Kish 有效样本量），旧样本多时 `nEff` 明显小于 `n`，排序时应据此打折。
- **趋势**：同一组里最近 180 天和更早各有至少 2 条卖出样本时，返回 `trend`：近期净收入中位数 ÷ 更早净收入中位数，如 `"1.180"` 表示近期卖得贵了 18%。
- **样本范围**：买入样本是不在回收站、成本已知的副本，按买入日期加权；卖出样本是售出中和已交易的销售明细，按销售日期加权，取消、退货、退款不计。
- **按介质分开**：介质归一为 `CD`、`LP`（含 7″、10″、12″ 黑胶）和 `other`（磁带、DVD、套装等），依据副本的发行资料格式和各碟介质；副本填了黑胶规格（`vinyl`）的一律按 `LP`。没有登记介质的副本按 `CD` 计：收藏以 CD 为主，黑胶和磁带通常会登记介质。`album` 与 `artist` 两级只统计和候选同介质的副本；候选没给 `format` 时，返回 `byFormat`，按介质分别给出。`release` 级本身就是同一版本，不再拆分。国际运费和整批费用也按介质分别统计，因为 LP 明显更重。

## 请求

请求头 `Authorization: Bearer <INSIGHT_TOKEN>`，响应带 `Cache-Control: no-store`。金额是人民币字符串，两位小数；比例是 0–1 的字符串，三位小数；天数是整数。利润率 = 利润 ÷ 净收入。卖出天数从买入日期算到销售日期。

### `GET /api/insight/profile`：买卖画像与成本模型

Agent 开工前读一次，用来决定找什么，以及怎么把网站标价换算成落地成本。

```json
{
  "asOf": "2026-11-24",
  "weighting": {"halfLifeDays": 180, "from": "2023-11-24"},
  "costModel": {
    "jpyPer100": {"current": "4.850", "currentDate": "2026-11-21", "paidMedian": "4.920"},
    "overseasShippingPerCopy": {"CD": {"median": "38.00", "n": 41, "nEff": 22.6}, "LP": {"median": "71.00", "n": 9, "nEff": 5.1}},
    "batchFeesPerCopy": {"CD": {"median": "6.00", "n": 41, "nEff": 22.6}, "LP": {"median": "6.00", "n": 9, "nEff": 5.1}},
    "domesticPostage": {"median": "7.00", "n": 33},
    "platformFeeRate": {"median": "0.006", "n": 33}
  },
  "turnover": {"daysToSell": {"median": 26, "n": 33}, "inStockDays": {"median": 74, "n": 58}},
  "top": {
    "artistsByProfit": [{"artist": "…", "format": "CD", "sold": 5, "nEff": 3.2, "profitMedian": "62.00", "marginMedian": "0.410", "trend": "1.150"}],
    "labelsByProfit": [{"label": "…", "format": "CD", "sold": 4, "profitMedian": "40.00", "marginMedian": "0.330"}],
    "artistsByCount": [{"artist": "…", "bought": 9, "held": 3}]
  }
}
```

- 成本模型、周转和排行都按「统计口径」加权；排行按艺人或厂牌 × 介质分组，按加权利润排序。
- `jpyPer100.current` 来自汇率模块的有效缓存，不在请求中联网；没有有效缓存时为 `null`，Agent 用 `paidMedian`。
- `overseasShippingPerCopy` 只统计走过打包运输的副本，取该副本分摊到的运费；`batchFeesPerCopy` 统计日元买入的副本，取整批费用分摊（不含国际运费，没有为 0）；`domesticPostage` 与 `platformFeeRate`（= 扣费 ÷ 成交价）来自卖出样本。
- `turnover.daysToSell` 按销售日期加权；`inStockDays` 是当前国内、海外库存从买入至今的天数，不加权。
- 排行各取前 10，至少卖出 2 次才进入利润排行。

### `POST /api/insight/evaluate`：批量评估候选（核心）

Agent 抓到一页商品后，一次提交 1–50 条候选。可另带 `halfLifeDays`。

```json
{
  "halfLifeDays": 180,
  "candidates": [
    {"ref": "suruga-123", "catalogNumber": "WPCR-0001", "barcode": "4943674000000",
     "artist": "…", "title": "…", "format": "CD",
     "price": "1980", "currency": "JPY", "shippingToWarehouse": "0"}
  ]
}
```

| 字段 | 说明 |
| --- | --- |
| `ref` | 必填，调用方自己的标识，1–100 字，原样返回 |
| `catalogNumber` / `barcode` | 至少给一项，或给 `artist`（可加 `title`）；有编号或条码时优先精确匹配，编号按 Obi 的归一规则比较（大小写、空格、连字符不敏感） |
| `artist` / `title` / `format` | 名称匹配与同艺人参考用；`format` 用来区分 CD、LP 等 |
| `price` + `currency` | 网站标价，`JPY` 或 `CNY`；省略时只返回历史，不估算 |
| `shippingToWarehouse` | 可选，商品到转运仓的运费，与 `currency` 同币种，默认 `0` |

响应为 `{"asOf": …, "weighting": …, "results": […]}`，`results` 与提交顺序一致，每条为：

```json
{
  "ref": "suruga-123",
  "match": {"by": "catalogNumber", "level": "release"},
  "owned": {"held": 1, "inTransit": 0},
  "history": {
    "bought": 3, "costMedian": "118.00", "costRange": ["96.00", "141.00"],
    "sold": 2, "nEff": 1.8, "netMedian": "182.00", "profitMedian": "61.00", "marginMedian": "0.335", "trend": null,
    "daysToSellMedian": 19, "listedUnsold": 1, "listedUnsoldDaysMax": 63
  },
  "estimate": {
    "landedCost": "140.03",
    "parts": {"item": "96.03", "shippingToWarehouse": "0.00", "overseasShipping": "38.00", "batchFees": "6.00", "rate": "4.850"},
    "expectedNet": "182.00", "expectedProfit": "41.97", "expectedMargin": "0.231",
    "basis": "release", "n": 2, "nEff": 1.8
  },
  "notes": ["已有 1 张在库", "另有 1 张已上架 63 天未售出"]
}
```

- `match.level` 为 `release`（编号或条码精确命中同一版本）、`album`（同艺人同专辑、其他版本）、`artist`（只有同艺人）或 `none`。名称匹配不会给出 `release`。
- `owned` 沿用已购查询的状态口径：`held` 含国内、海外库存与上架未成交，`inTransit` 为入库在途。
- `history` 只统计 `match.level` 那一级，并按「统计口径」加权、按介质分开；`level` 为 `artist` 时是该艺人同介质副本的统计，`owned` 为 `null`。`album` 或 `artist` 级且候选没给 `format` 时，`history` 为 `null`，另返回 `byFormat: {"CD": {…}, "LP": {…}}`，只列有副本的介质。
- `costRange` 至少 3 条买入样本才给，否则为 `null`：两条样本的 10%–90% 分位就是两笔原值。
- `listedUnsold` 是这一级里已标记上架、仍在库的副本数；`listedUnsoldDaysMax` 从最近一次标记上架（闲鱼回执按核实时间）算到今天。
- `estimate.landedCost` = 标价折人民币 + 到仓运费 + 同介质的国际运费中位数 + 整批费用中位数。后两项只加在日元候选上；人民币候选视为国内购买，只有标价和到仓运费。日元用 `jpyPer100.current`，没有有效缓存时用 `paidMedian`，并在 `notes` 中注明；两者都没有时 `estimate` 为 `null`。候选没给 `format` 时按 CD 的运费估算。成本模型某项只有 1 条样本时按区间上限计入（保守），没有样本时按 0 计入，都会在 `notes` 中注明。
- `expectedNet` 取历史净收入中位数；没有卖出记录时为 `null`，`expectedProfit` 与 `expectedMargin` 随之为 `null`，由 Agent 用外部行情补。
- `basis`、`n` 与 `nEff` 说明估算依据哪一级、几条样本、近期有多少分量，排序时应据此打折。
- `notes` 是给人看的短句，不用于程序判断。

### `GET /api/insight/releases`：单张查询

查询参数与 `evaluate` 的一条候选相同（`catalogNumber`、`barcode`、`artist`、`title`、`format`、`price`、`currency`、`shippingToWarehouse`，可加 `halfLifeDays`），不需要 `ref`。返回单个对象，内容同 `evaluate` 的一条（`ref` 为 `null`）。供 Agent 深挖某一张时使用：

```http
GET /api/insight/releases?catalogNumber=WPCR-0001&format=CD&price=1980&currency=JPY
```

## 小样本

- 某一组只有 1 条样本时，金额字段改为区间 `{"low": "75.00", "high": "110.00"}`，不给精确值，避免反推出单笔交易；利润率、卖出天数这类比例和天数在不足 2 条时为 `null`。
- 区间按比例划分，不按固定金额：边界大约每档 ×1.5，取整数，依次为 10、15、22、33、50、75、110、170、250、380、570、850、1300、2000……。这样不管 30 元还是 800 元的唱片，区间宽度都约为 ±20%：低价不会被一档吞掉，高价也不会被切得过细。
- 亏损按绝对值取档后取负，如 −30 元为 `{"low": "-33.00", "high": "-22.00"}`；10 元以下为 0–10。
- 区间用数字上下限而不是文字标签，Agent 可以直接算。`estimate` 随之给出 `expectedProfit` 的上下限（净收入上下限减落地成本），`expectedMargin` 为 `null`，`n` 为 1。
- 没有样本时，对应统计为 `null`，不用其他级别的数据冒充。

## 错误

| 状态 | 含义 |
| --- | --- |
| 404 | 未开通（没有任何令牌具有 `insight:read`） |
| 401 | 令牌无效 |
| 403 | 令牌有效但不含 `insight:read` |
| 400 | 参数无效：候选不在 1–50 条、`ref` 重复、有未知字段、缺少可匹配字段、金额或币种无效、`halfLifeDays` 超出范围 |

所有错误响应都是带 `error` 的 JSON。

## 使用流程

1. `GET profile`：了解偏好、成本参数和周转。
2. Agent 在唱片网站抓候选列表（在 Obi 之外）。
3. `POST evaluate`：标出已有的、估算落地成本和预计利润。
4. Agent 交叉核对外部行情（闲鱼在售与成交、Discogs 成交记录）；`expectedNet` 为空或 `n` 小时以外部行情为主。
5. Agent 按预计利润、利润率、周转天数和样本数排序，给你短名单，附商品链接与理由。
6. 你自己下单；到货后照常录入 Obi，新数据自动进入下一次评估。

## 不做的事

- 不抓取或缓存任何唱片网站和行情数据。
- 不保存候选、短名单或推荐理由。需要在 App 里管理候选时，另设「关注清单」模块，单独决策。
- 不按品相区分价格：品相差异由 Agent 依据商品描述说明。
- 不接受下单、出价或预算授权。
