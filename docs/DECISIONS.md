## D-001 · 接入 ai-kit：存量文件进白名单，新改动照常受检
- **日期**：2026-10-17
- **状态**：生效中
- **背景**：项目早于 ai-kit，存在超过 200 行的文件、集中放在 `styles/` 的样式、含字面量颜色的文件。
- **决定**：这些文件列入 `.ai-kit/legacy.txt`，不受 R1/R2/R10/R11 检查；pre-commit 只检查暂存文件；新文件与新建组件必须满足全部规则。仍保留 `tools/hooks` 数据泄漏扫描并先于 ai-kit 检查运行。
- **代价**：白名单内的文件被改动时不会被拦；需靠评审与逐步拆分把它们移出白名单。
- **何时重新评估**：白名单文件数降到 30 以下，或每次动到某个白名单文件时顺手拆分并移除其条目。

## D-002 · 品牌色与语义色保持不变；颜色仍只经 token
- **日期**：2026-10-17
- **状态**：生效中
- **背景**：ai-kit 的 R1 要求灰度。本产品的黄色主色、深浅双主题与语义色是用户已定案的界面规范（AGENTS.md「界面规则」）。
- **决定**：R1（灰度）不适用于本产品既有界面；R2（颜色只经 token，不写字面量）适用于所有新代码。新增色彩需求先加 token。
- **代价**：无。
- **何时重新评估**：用户明确要求改为灰度视觉时。

## D-003 · 新建/重写的单元组件样式与组件同目录
- **日期**：2026-10-17
- **状态**：生效中
- **背景**：AGENTS.md 原规定样式集中放 `src/styles/<模块>.css`；用户新要求「一个组件一个文件，样式也在文件里，不要堆在同一目录」。
- **决定**：新建或重写的可复用单元组件放 `components/ui/<Name>/` 目录：`<Name>.tsx` + `<Name>.css` + 头部注释，并在 `REGISTRY.md` 登记。既有页面级样式仍在 `styles/`，随改动逐步迁移。
- **代价**：过渡期两种位置并存。
- **何时重新评估**：`styles/` 下文件全部迁移完成时。

- **日期**：2026-10-17
- **状态**：生效中
- **背景**：原先宿主直接携带完整引擎（查看器、生成器、模型），无法按需安装；旧约定是「不引入动态插件加载」。

## D-009 · 允许 Service Worker 在本机缓存专辑封面，退出登录时清空
- **日期**：2026-10-19
- **状态**：生效中
- **背景**：手机上封面需从家中树莓派经公网逐张下载（约 100KB/张），每次打开都会出现空白格子到封面的可见跳变。封面按内容哈希命名、不可变，缓存风险低于库存数据本身。
- **决定**：`static/sw.js` 对 `/api/cover/` 采用缓存优先，仅保存 200 响应；`web/src/core/cover-cache.ts` 在退出登录时删除 `album-covers` 缓存。会话、交易请求及其他私有 API 响应仍禁止缓存，原「不缓存私有库存」约定相应收窄为本条例外。
- **代价**：封面图片保存在设备本机 Cache Storage 中，设备丢失或被他人访问时可能暴露封面；在其他设备修改密码导致的登出不会清空这些设备上的封面缓存，需手动清除站点数据；Service Worker 无法注册的环境（如内置浏览器面板）下缓存不生效。
- **何时重新评估**：封面需要按设备或按用户隔离、或改为服务器侧缩略图缓存时；或发现 Service Worker 在目标设备上缓存行为异常时。

## D-010 · 发布脚本：预检、按 schema 恢复快照、快照轮换、公网检查
- **日期**：2026-10-19
- **状态**：生效中
- **背景**：`tools/deploy.sh` 能自动快照与回滚，但服务器上积了 40 份发布前快照（518MB），回滚只切代码不管库结构，发布不看工作树是否干净、测试是否通过，也不检查公网入口。
- **决定**：本机构建时先做预检（未提交改动中止、未推送警告、默认跑测试、构建产物须与已提交的 `static/` 一致）；回滚时若库 schema 已被新版本改动则先恢复发布前快照；发布成功后只保留最近 `KEEP_SNAPSHOTS` 份快照；可选 `PUBLIC_URL` 公网检查（失败退出码 3，不回滚）；锁记录持有者并给出 `--unlock`；服务器 `deploy.log` 记录每次发布；ssh 复用连接；个人默认值写 `data/deploy.env`。补丁更新器走 `DEPLOY_HOST=local` + `PACKAGE_PATH`，不读配置、不做预检。
- **代价**：默认发布更慢（多跑一遍测试，约 1 分钟，可 `--skip-tests`）；旧快照在下次发布时会被一次性清理（按 5 份保留）；自动恢复快照只在 schema 变化时触发，同 schema 的数据迁移问题仍需人工判断。
- **何时重新评估**：增加多台服务器、或改用容器发布时。

## D-012 · 按副本准备售卖草稿，独立 ChatGPT OAuth 优先
- **日期**：2026-10-19
- **状态**：生效中
- **背景**：用户要求识别已有照片的版本与外观，生成人工闲鱼发布所需文案和图片包；确认只做到复制、下载，并明确选择优先官方 ChatGPT OAuth、保留兼容 API。
- **决定**：仅在交易模块增加售卖辅助；不恢复 D-005 删除的照片录入、旧识别路由或实体生成。观察附照片编号，版本沿现有目录检索，不自动选版；核对后显式生成正文。草稿以副本字段保存，不改上架状态，显式上架与草稿同一事务；导出只含有序选图。复用现有抽屉、Dropdown、灯箱与下载工具。
- **模型与认证**：新增单职责标准库服务，经 Services 注入。官方 SIWC 独立动态客户端、PKCE/state/nonce、固定 issuer/JWKS 的 RS256 校验；loopback 本机授权，自托管用本机 CLI 授权后安全导入，保留目标 host ID。账户凭据以权限受限文件保存并串行刷新，业务库与备份不含令牌。API 使用服务端环境变量，需显式切换；失败不切换计费来源。
- **代价**：官方订阅调用处于预览协议，账号模型与权限需现场核验；新增纯标准库 RS256 校验需覆盖签名/issuer/audience/nonce/有效期。进行中的任务保存在内存，服务重启需重试；已保存草稿可恢复。图片细节受原上传压缩限制。根模块新增 domain_listing.py，已同步 Docker 与发布包校验器；旧更新器尚不认识该根模块时需手动部署本版。
- **何时重新评估**：官方 OAuth 协议变化、需要跨实例任务恢复、闲鱼上传规则变化，或用户要求自动填表/发布时。

## D-014 · 条码检索增加 Discogs 备用来源与手动录入未收录版本
- **日期**：2026-10-19
- **状态**：生效中
- **背景**：日版 IECP-50008（Red，2008）等版本 MusicBrainz 未收录；检索无结果后表单无出路，MusicBrainz 偶发限流 503 时也只提示“暂时不可用”，用户无法录入。
- **决定**：MusicBrainz 优先；无精确匹配或不可用时查 Discogs 公开接口（精确条码 / 目录号、仅 CD，候选仍须人工选择，不按标题猜）。接口返回各来源状态；两来源都不可用才报错，都没有则前端提示并提供手动录入。新增 `discogsReleaseId`、`manualRelease` 两个发行资料字段；保存时 Discogs 版本按其条码核对，手动版本不核对。前端查询加 70 秒兜底超时，不再无限“查询中”。
- **代价**：Discogs 公开接口约每分钟 25 次，客户端串行 2.5 秒间隔；数据为社区维护，国家名仅映射常见项；无 MusicBrainz ID 的记录没有 CAA 封面、3D 与艺人反查依据，封面靠 iTunes 或手动。手动录入的名称与资料完全由用户负责。
- **何时重新评估**：需要 Discogs 令牌提高限额、要拉取 Discogs 封面，或用户要求将未收录版本回写第三方库时。

## D-013 · 多服务商连接与能力目录；Claude 使用官方 CLI OAuth
- **日期**：2026-10-19
- **状态**：生效中
- **背景**：用户要求同时登录多家服务商，选择 OpenAI OAuth、DeepSeek、Anthropic OAuth 的模型及思考强度。
- **决定**：保留各连接，按服务商/授权身份隔离模型配置和目录；显式拉取模型并校验能力，只提供目录声明的强度，默认省略强度参数。任务持有启动快照，不随界面切换。DeepSeek 用官方多模态 Chat Completions/API Key；OpenAI 复用独立 SIWC/Responses。Anthropic 不冒充其他客户端，不直接借 CLI token 请求 API；使用官方 Claude Code auth 与 print/SDK 协议，通过标准库 subprocess 调用可选 CLI，独立授权目录。使用安全模式禁用自定义上下文，无工具/MCP/钩子，无会话持久化；授权变化与分析/目录读取互斥。配置/密钥在私密文件，状态只返回安全摘要。保持原兼容 API 服务端环境变量路径。
- **代价**：Claude CLI 是可选外部依赖，默认 Docker 无此通道，需用户在同一服务环境安装；CLI 初始化模型目录是版本协议，升级可能变化，失败须更新。服务商未声明图片能力时保留未知，不能宣称实际可用；模型列表不等于账户真实推理成功。订阅/API 计费规则由各家账户决定。DeepSeek 断开设置明确覆盖环境变量，重新连接需显式输入密钥。
- **何时重新评估**：官方提供适合本应用的 Anthropic 直连 OAuth 规范、CLI 目录协议变化或服务商调整视觉/思考能力元数据时。

## D-015 · 专辑详情分层：摘要 + 发行资料页 + 管理页；编辑只放原始信息；数字实体归收藏展示

## D-018 · `/api/state` 只下发登记的设置，按 ETag 回 304 或只发变化的行
- **日期**：2026-10-21
- **状态**：已实现
- **背景**：
  - 前端在每次写入后、以及回到页签时，都整份重拉 `/api/state`（约 400KB，gzip 后约 70KB），然后整页重渲染。手机经公网访问时，这是保存后「慢一拍」的主要来源（见日志 2026-10-21-bulk-feedback-first）。
  - `state()` 把 `meta` 表整份当作 `settings` 下发，包括实体目录、艺人身份、商家缓存，以及旧版导入时原样保留的键（如 RYM 令牌）。前端实际只读其中的 `showcase-groups-v1`。
  - 原计划是「写接口返回改动后的记录，前端就地更新」，那要逐个改约 20 个写接口和调用点，还要在前端重算成本和利润。
- **决定**：
  - `settings` 只下发 `storage.STATE_SETTINGS` 里登记的键。`state()` 不再读整张 `meta` 表，也不再带每次都会变的 `createdAt`。
  - 响应带内容哈希 ETag，前端 `refresh()` 手动带上 `If-None-Match`。内容没变时回 304，前端不更新状态、不重渲染。
  - 服务器记住最近 8 份状态里每一行的摘要（`server/state_sync.py`）。客户端的基线还在时，只回变化的行和消失的行，前端在本地拼回完整状态，没变的行保持原对象。拼法在两端一一对应，用测试保证拼出的结果与整份下发逐字段相同（含行序）。
  - 写接口和调用点都不改，所有走 `refresh()` 的路径自动受益。
  - 响应仍为 `no-store`（D-009 不变）。手动带 If-None-Match 的请求不经浏览器缓存。
- **代价**：
  - 每次请求多算一遍行摘要：1500 张专辑时本机约 13ms，实际数据量下为几毫秒。
  - 进程重启或基线太旧时退回整份下发。
  - 增量格式是前后端的私有约定，改一边必须同步另一边，两边各有一组测试守着。
- **何时重新评估**：收藏量大到整份构建 `state()` 本身变慢时（改为按表分页或按版本号增量）；或前端需要离线写入时。

## D-019 · 没有服务器也能用：同一套后端在浏览器里运行（本机模式）
- **日期**：2026-10-22
- **状态**：已实现（第一版）
- **背景**：Obi 是单用户、数据在自己设备上的工具，部署路径只有 Docker / 裸机。没有服务器的人（主要是手机用户）用不了；有服务器的人仍应以服务器为主。
- **决定**：
  - 两种模式共用同一份前端与同一份 Python 后端。服务器模式（Docker / 裸机）一行不变；本机模式把静态站点交给任意静态托管，后端用 Pyodide（WebAssembly 里的 CPython）在页面的 Web Worker 里运行。
  - `/api/*` 由 Service Worker（`static/local/sw-local.js`，构建时替换为站点的 `sw.js`）经 BroadcastChannel 转给 Worker（`engine-worker.js`），Worker 调 `server/local_entry.py` 的 `Engine.handle()`，它直接走现有路由表。前端的 `fetch` / `<img src="/api/…">` / 下载链接一处都不用改。
  - 数据在浏览器里：SQLite 与照片放 Emscripten 文件系统，挂 IDBFS 持久化到 IndexedDB；写请求落盘后才回复。同一时刻只允许一个窗口持有引擎（Web Lock），第二个窗口提示后停止，避免两份内存库互相覆盖。
  - 前端靠 `index.html` 里的 `<meta name="diedu-local">` 判断是否静态站点（`core/backend.ts`）。该标记只由 `web/scripts/build-local.mjs` 写进 `dist-local/`，服务器镜像与 `static/` 里没有，所以服务器部署零行为变化、没有多余请求。
  - 浏览器与服务器的差别全部在 `local_entry.py` 里抹平：线程池换成就地执行、不启动任何后台线程、`urllib` 出站请求改走同步 XHR（受 CORS 约束，MusicBrainz / iTunes / Cover Art Archive / 汇率接口均已实测可直连）、`fcntl` 空实现。业务代码与路由表不为本机模式分叉。
  - 构建：`npm --prefix web run build:local` 生成 `dist-local/`（约 20 MB：站点 + Pyodide 运行环境 + Python 源码 + 预缓存清单）。它不进 `static/`、不进 Docker 镜像、不进 git。站点整体预缓存，装到主屏后可断网使用。
  - 两种模式之间用现有「完整备份」互通，不做同步。
- **代价**：
  - 首次打开要下载约 20 MB（之后走缓存）。
  - 引擎单线程：一次联网较慢的请求（如封面搜索，实测可达十几秒）期间，其他请求排队。
  - 浏览器可能清理站点数据（iOS Safari 尤其）。已申请持久存储，但是否授予由浏览器决定，必须靠定期导出备份兜底。
  - 本机模式不含：登录与密码、售卖照片识别（服务商 OAuth）、3D 引擎插件的安装与生成、商家图标自动发现、每日快照。设置页相应入口目前仍会显示（I-012）。
  - Python 源码在构建时整份打包，每次发布静态站点都要重新执行 `build:local`。
- **何时重新评估**：
  - 引擎排队影响体验时（改成多个 Worker 或把慢请求移出引擎）。
  - 需要多设备同步时（本方案只靠备份互通）。
  - Pyodide 版本升级（`web/package.json` 固定为精确版本，sqlite3 扩展包随版本）。

### D-019 补充（2026-10-22）：外网查询独立引擎
同步 XHR 会占住引擎，而 JSPI 在 Chromium / WebKit 均不可用，故起第二个 Worker 专管不碰账本的慢查询（汇率、发行资料、封面搜索下载），账本与艺人资料留在 main。拒绝的做法：优先级队列（无法抢占）、把查询结果回传 main 写入（复杂且无必要）。

## D-023 · 安卓补丁只换网页内容：免确认、无感知；功能版本才重装
- **日期**：2026-10-22
- **状态**：生效中（取代 D-022 中「不做网页内容热更新」一条）
- **背景**：用户要求补丁自己更新、用户无感知，而不是每次让用户确认安装新的安装包。系统不允许应用静默重装自己（Android 10/11 必弹确认；12+ 也要先授权），所以补丁不能走重装。
- **决定**：
  - 约定：**同一 主.次 版本内的补丁只改网页内容与 Python 后端**（都在 `dist-local` 里）；动了原生外壳（`android/` 的 Java、权限、桥接）必须升次版本。
  - CI 在发布 Release 时除 `Obi-<tag>.apk` 外，再上传 `Obi-<tag>-web.zip` + `.sha256` + `.sig`（`android/make-web-patch.sh`：dist-local 去掉 Pyodide 运行时，加 `content.json`；用安装包同一把 RSA 密钥签名）。内容包先于安装包上传。
  - 应用检查到同 主.次 的更高版本 → 下载内容包，校验 SHA-256，再用**自己安装包的签名证书公钥**验签（只有持有发布密钥的发布才被接受，GitHub 账号被盗也不够），解压到应用私有目录（防路径穿越、限大小与文件数，`content.json` 的 tag 必须等于 Release tag 防降级冒充）。页面由外壳优先从该目录提供，没有的文件（Pyodide）仍取安装包自带。**任何安卓版本都不需要用户确认。**
  - 生效：冷启动时页面加载后立即换上；应用在后台超过 30 秒再回来时换上（避免正在填写时重载）。换上 = 注销旧 Service Worker、清缓存、重载一次；数据在 IndexedDB，不受影响。
  - 不同 主.次 的新版本仍走 D-022 的安装包更新。安装了更高版本的安装包后，补丁目录自动作废并清理。
- **代价**：用户会在回到应用时看到一次一两秒的重新载入；补丁依赖 Release 附件齐全（缺附件时重试）。第一次获得这个能力需要装一次新安装包（v3.3.0），此前的版本不带补丁逻辑。
- **何时重新评估**：补丁需要改原生代码的情况变多，或上架商店。

### D-023 补充（2026-10-24，v3.7.0）：补丁改原生由发布闸门拦下
v3.6.22–v3.6.37 在补丁版本里改了 `MainActivity`（沉浸展示），这些改动只以网页内容包下发，用户手机上的外壳从未更新，修复全部落空。现由 `tools/check_android_line.py` 把关：补丁 tag 相对 `vX.Y.0` 改了 `android/app/src` 或 gradle 文件即失败；`tools/package_app.py` 打包与 `android.yml` 构建前都会先跑。界面「应用更新」在两者不同时同时显示安装包版本。

### D-022 补充（2026-10-22，v3.5.0）：安装包更新改为用户点击才装
用户明确要求出现按钮由用户点击安装，不要离开应用后自动装。D-022 中「离开应用 / 后台时静默安装」整条取消：安装包更新只在用户点「安装」（设置页按钮或前台确认框）后进行；「允许安装未知应用」仍可减少系统确认步骤。自动、无感知的只有 D-023 的网页内容补丁。

## D-024 · 版本号：构建号随部署走，正式版攒批再打
- **日期**：2026-10-24
- **状态**：生效中
- **背景**：每推一次修复就打一个补丁 tag（v3.6 下 38 个补丁，2026-10-24 一天 v3.8.0–v3.8.5 都在调同一个动画），版本号既当「构建标识」又当「对用户说更新了什么」，涨得很快、更新说明也碎。
- **决定**：日常部署不打 tag，版本用 `git describe` 构建号（`v3.8.5-3-gabc1234`）；一批改动做完、真机确认后才打正式 tag。`CHANGELOG.md` 先记在「未发布」，打正式版时归入版本段。「更新说明」按构建号所基于的正式版比较，只在新正式版后弹出；服务器补丁更新器（`tools/update_release.py`）接受构建号作为已装版本，按其基础正式版选补丁。
- **代价**：安卓手机只认 GitHub 正式 Release（D-022 / D-023），未打 tag 的构建到不了手机；需要真机验证时仍要打正式版。
- **何时重新评估**：真机调试仍频繁需要打 tag 时，考虑给安卓加「测试通道」接收预发布（改原生，需升次版本）。

## D-025 · 父子页：两种容器保留，左缘返回手势只有一份
- **日期**：2026-10-24
- **状态**：生效中
- **背景**：应用里有两种父子页：抽屉页栈（`state/useDrawerStack` + `components/ui/Drawer`，专辑详情 → 管理 → 编辑买入信息等）和「更多」里的路由子页（`core/page-back` 的 BACK_TARGET + `core/nav` + `hooks/useEdgeSwipeBack` + `components/PeekUnderlay`）。两边各写了一套左缘右划，起手判定、拦系统手势、阈值都不同；路由子页起手不拦，iOS 慢划时被系统返回手势抢走（内容瞬间弹回再显示上一级）。
- **决定**：
  - 两种容器语义不同，保留：抽屉 = 围绕某张专辑的上下文（关掉回到原处，页面常驻、返回不重载）；路由子页 = 应用导航（有地址、刷新可回到）。
  - 手势统一走 `core/edge-swipe.ts`：起手 28px 内即 preventDefault（贴边按钮 / 链接除外）、方向锁定前也拦、末段速度、多指 / touchcancel / 丢失 touchend 一律回弹；「算不算返回」统一为拖过宽度 30% 或 30px 以上甩动（> 0.45px/ms）。容器只负责画面（抽屉动页面层，子页动内容 + 垫底页）。
  - 新增父子页时：属于某条记录的放进抽屉页栈（`spec.back`），属于导航的登记 BACK_TARGET；不得再写第三套手势。
- **代价**：左缘 28px 内起手的纵向滚动不再生效（抽屉此前已如此）。
- **何时重新评估**：路由子页超过一层以上嵌套变多，或 PeekUnderlay 需要垫更多种页面时，考虑把子页也做成常驻页栈。

## D-026 · 数据进出：完整备份是含照片的 zip，表格只导出，移除 albums.json 导入
- **日期**：2026-10-24
- **状态**：生效中
- **背景**：设置 · 数据里「下载完整备份 / 恢复」和「导入与导出」两个都是「选一个 .json」，用户分不清哪个替换整本、哪个往里加；「完整备份」其实不含照片和自己上传的封面（服务器要另备份数据目录，本机模式根本没有途径）；albums.json 导入只服务早期一次性迁移，用户已不再使用，也不需要从表格批量添加。
- **决定**：
  - 按数据去向分三块，各只有一种语义：**备份与恢复**（Obi ↔ Obi，不丢东西，整本替换）、**导出表格**（Obi → CSV，只读）、回收站 / 最近操作。
  - 完整备份改为 zip（`server/archive.py`）：`manifest.json`（逐文件大小与 sha256）+ `ledger.json`（原 JSON 完整备份）+ `photos/` `covers/` `digital-twins/` `engine-models/`；不含凭据、插件程序与缓存。前两项不压缩，网页无需解压库即可读出确认信息。
  - 恢复走整文件上传 `POST /api/restore-archive`（`routes.UPLOAD`，不经 JSON，上限 4 GB；服务器与本机模式同一处理函数）。整包校验（清单、大小、sha256、路径白名单、版本）并解到暂存目录后才动数据；账本恢复前照旧自动快照，被替换的文件夹移到 `backups/pre-restore/`（只留最近一次）。旧版 `.json` 完整备份仍可恢复。
  - 恢复入口先识别文件：CSV 表格、旧 albums.json、非 Obi 的 zip 直接说明原因。
  - 删除 albums.json 导入（`/api/import*`、设置页导入、启动时自动导入 `data/albums.json`）。已导入记录的 `sourceId` / `original` 字段保留。
- **代价**：备份包可能几百 MB，生成时整包在内存里组装；反向代理需放宽恢复接口的请求体上限（见部署说明）。服务器每日快照仍只有账本。
- **何时重新评估**：备份包常超过 1 GB，或手机上生成 / 下载明显卡顿时，改为流式生成或分卷。

## D-027 · 版本封面：此版本的优先，没有再借更宽泛的
- **日期**：2026-10-25
- **状态**：生效中
- **背景**：版本卡片只看这个版本自己在 Cover Art Archive 的正面图，没有就显示「无封面」；而「选用此版本」后的自动匹配会再试 iTunes，「换一张封面」更会宽搜，于是同一张专辑先说没有、后面又找到。三处各写一套顺序，查询页按文字搜时另传了同专辑封面，按条码查时没传。
- **决定**：
  - 一个版本的封面按同一顺序找：① 此版本自己的正面图 → ② 同一张专辑的封面（release-group，组内 CD 版本优先）→ ③ 同名同艺人的 iTunes 数字封面。②③ 只认名字精确对上的，由服务端 `covers/fallback` 判定。
  - 版本卡片、「选用此版本」后的自动匹配、查询页「以此入库」带入的表单共用这一顺序（`core/version-cover.ts`）；借来的封面注明「不一定是这个版本的包装」。
  - 「换一张封面」保持宽搜、由用户点选，不受此约束。
- **代价**：此版本没有图时多一次服务端查询（MusicBrainz / iTunes 有限速，卡片多时会慢几秒）；借来的封面可能与实物包装不同。
- **何时重新评估**：用户反映借来的封面常与实物不符时，改为只在卡片上展示、不自动写入记录。

## D-028 · 条码备用源改为 Deezer；Bandcamp 只作封面地址来源
- **日期**：2026-10-28
- **状态**：生效中
- **背景**：
  - 二次元 / 特摄实体盘常出现「扫码没有任何结果」。实测 Discogs 的搜索接口不索引条码（`barcode=` 与 `q=<JAN>` 均返回 0，`catno=` 正常），D-014 设计的「MusicBrainz 没命中就查 Discogs 精确条码」实际一直空转。
  - Deezer 的 `album/upc:<JAN>` 可精确命中日本商业盘（日本 CD 的 JAN 与数字版 UPC 同码），返回厂牌、日期、曲目与封面。
  - Bandcamp 没有条码与唱片编号体系；主站（含 API 与专辑页）对 Python 标准库的 TLS 指纹返回挑战页（I-017），但图片 CDN `f4.bcbits.com` 可正常访问。
- **决定**：
  - 条码链路改为 **MusicBrainz → Deezer**；Discogs 的条码分支删除，只保留唱片编号链路 **MusicBrainz → Discogs**。
  - 新增发行资料字段 `deezerId`；Deezer 只收录数字发行，不写 `format` 为 CD、不填碟数。`unofficial` 仍要求不绑定任何资料库版本。
  - **Bandcamp 不作为发行版数据源**：不建候选、不加身份字段、不参与检索与条码核对。只在封面面板提供「从网址」：粘贴 Bandcamp 图片地址（`f4.bcbits.com`），服务端按 `covers.artwork_url` 白名单下载并落盘，来源记为 Bandcamp。
  - 来源分发收敛到 `web/src/core/release-source.ts`（MusicBrainz / Discogs / Deezer），页面不再写 `source === 'discogs' ? … : MusicBrainz`。
- **代价**：
  - Deezer 覆盖数字发行：日本「通常盘」常能命中，初回 / 限定盘的独立 JAN 往往没有，仍需 Discogs 编号或手动录入。
  - Bandcamp 封面需要用户自己在专辑页右键复制图片地址，无法自动搜索。
  - 本机模式（D-019）不接 Deezer：它不返回 CORS 头，浏览器同步 XHR 取不到。
- **何时重新评估**：Bandcamp 放宽反爬或开放官方 API 时，重新评估是否恢复名称检索；取得 ORICON API 或 VGMdb 官方 API 时补特摄限定盘。

### D-019 补充（2026-10-28）：售卖识别进入安卓本机模式
安卓外壳新增原生回环中继，本机模式可以组装售卖辅助（仅 OpenCode / DeepSeek 密钥通道）。浏览器静态站点没有中继，仍不含售卖照片识别。见 D-030。

## D-029 · 售卖识别新增 OpenCode（Go 订阅 / 按量余额）服务商
- **日期**：2026-10-28
- **状态**：生效中（界面标 Beta）
- **背景**：用户使用 OpenCode Go 订阅，要求把它作为独立的视觉模型服务商接入售卖照片识别，而不是伪装成「OpenAI 兼容 API」。OpenCode Console 同时提供 Go（订阅）与按量余额两条通道，使用同一把 Console API Key，区别只在网关地址；两条通道都提供 OpenAI / Anthropic / Gemini 兼容入口，并把请求翻译到模型的原生协议。
- **决定**：
  - 新增独立服务商 id `opencode`，密钥在设置页填写（只显示末四位，保存在服务端受限文件），保留 `OPENCODE_API_KEY` 环境变量回退；断开设置抑制回接。
  - 计费通道（`opencodeLane`：`go` / `zen`）保存在服务商配置里；身份指纹包含计费通道与网关地址，模型目录与选择按通道隔离，切回旧通道恢复原选择。
  - 模型目录取 `<base>/v1/models`；分析统一走 `<base>/openai/v1/chat/completions`（网关负责翻译成模型原生协议），带每个任务生成的 `x-opencode-session` 会话头与自有 User-Agent，不发送 `response_format`。
  - 目录不返回图片与思考强度能力：按「未声明」展示，不按模型名猜测；仅文字模型在分析时由服务商响应暴露错误。免费档模型（仅限 OpenCode 客户端）或工作区未授权时，分析请求返回 403，界面显示「可能仅限 OpenCode 客户端使用，或工作区未授权此模型」，不自动切换计费来源。网关地址可用 `OPENCODE_API_BASE` 覆盖（仅 HTTPS 或本机 HTTP，供自建代理与验收）。
- **代价**：目录没有能力元数据，无法像 OpenAI / Claude 那样预先屏蔽仅文字模型；Go 面向编码 agent 流量、按模型有月度额度，非编码用途可能受限。翻译层行为随 OpenCode 更新，失败需按其文档调整；单次分析只发送本副本照片与名称/艺人，失败不自动切换计费来源。
- **何时重新评估**：OpenCode 在模型目录中提供图片 / 思考能力元数据，或 Go 的用途与额度规则不再适合本应用时。

## D-030 · 安卓本机模式：原生回环中继跑售卖照片识别
- **日期**：2026-10-28
- **状态**：生效中
- **背景**：用户要求安卓本机版也能用 OpenCode 做售卖照片识别。实测 OpenCode 的 CORS 预检 `OPTIONS /inference/go/openai/v1/chat/completions` 返回 404、没有 `Access-Control-Allow-*`，浏览器里的 Pyodide 无法直连；本机模式原先也没有组装售卖服务，且分析用线程池、ChatGPT 授权用 fcntl、Claude 用子进程，浏览器里都不可用。
- **决定**：
  - 安卓外壳新增 `ModelRelay`：只绑定 `127.0.0.1` 的随机端口，路径带每次启动随机生成的 token；只允许 `Origin: https://appassets.androidplatform.net`，只转发 `/p/<token>/opencode/inference/...` 到 `https://opencode.ai/inference/...`；方法限 GET / POST，请求体上限 40 MB，只透传 Authorization / Content-Type / X-Opencode-Session / Accept，补 CORS、`Access-Control-Allow-Private-Network` 与固定 User-Agent。拒绝把它扩成任意主机代理。
  - WebView 保持 `https://appassets.androidplatform.net` 源（不能换源，否则 IndexedDB 里的账本读不到），只对回环中继开启 `MIXED_CONTENT_ALWAYS_ALLOW`；`network_security_config` 只对 127.0.0.1 / localhost 放行明文。
  - 页面经 `ObiAndroid.modelRelay()` 取得中继地址，启动引擎时写入 `OPENCODE_RELAY_BASE`；`api_endpoint('opencode')` 只按这个前缀改写。没有中继（浏览器静态站点）时 `local_entry.build_local()` 不组装 `listings`，售卖入口维持不可用。
  - 本机售卖只开放 OpenCode / DeepSeek 的密钥通道；ChatGPT OAuth、Claude Code 与兼容 API 仍仅服务器版。默认服务商在本地从 OpenAI / Claude 自动落到 OpenCode。
  - Pyodide 不能起线程：`ListingAnalysis(inline=True)` 在请求内直接跑完；本机 Service Worker 只把 `/api/listing/analyze` 的等待上限放宽到 300 秒。
  - 这是原生外壳改动，按 D-023 必须随**次版本**发布（3.11.0），不能当补丁下发。
- **代价**：WebView 全局允许混合内容，安全性弱于默认；回环中继多了一个本机监听端口与代理面（用 token + Origin + 主机/路径白名单收敛）；本机分析期间主引擎 Worker 被占用，其他 /api 请求要等它结束；ChatGPT / Claude 仍无法在本机使用。
- **何时重新评估**：OpenCode 支持 CORS 后可删掉中继；WebView 支持按源放行混合内容；或安卓版改为可选连接服务器。
