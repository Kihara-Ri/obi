# 架构决策

只增不删（废弃的标记"已废弃"）。代码里的妥协处加注释 `// 见 D-001`。

## D-001 · 接入 ai-kit：存量文件进白名单，新改动照常受检
- **日期**：2026-10-17
- **状态**：生效中
- **背景**：项目早于 ai-kit，存在超过 200 行的文件、集中放在 `styles/` 的样式、含字面量颜色的文件。
- **决定**：这些文件列入 `.ai-kit/legacy.txt`，不受 R1/R2/R10/R11 检查；pre-commit 只检查暂存文件；新文件与新建组件必须满足全部规则。仍保留 `tools/hooks` 数据泄漏扫描并先于 ai-kit 检查运行。
- **代价**：白名单内的文件被改动时不会被拦；需靠评审与逐步拆分把它们移出白名单。
- **何时重新评估**：白名单文件数降到 30 以下，或每次动到某个白名单文件时顺手拆分并移除其条目。

## D-002 · 品牌色与语义色保持不变；颜色仍只经 token
- **日期**：2026-10-17
- **状态**：生效中
- **背景**：ai-kit 的 R1 要求灰度。本产品的黄色主色、深浅双主题与语义色是用户已定案的界面规范（AGENTS.md「界面规则」）。
- **决定**：R1（灰度）不适用于本产品既有界面；R2（颜色只经 token，不写字面量）适用于所有新代码。新增色彩需求先加 token。
- **代价**：无。
- **何时重新评估**：用户明确要求改为灰度视觉时。

## D-003 · 新建/重写的单元组件样式与组件同目录
- **日期**：2026-10-17
- **状态**：生效中
- **背景**：AGENTS.md 原规定样式集中放 `src/styles/<模块>.css`；用户新要求「一个组件一个文件，样式也在文件里，不要堆在同一目录」。
- **决定**：新建或重写的可复用单元组件放 `components/ui/<Name>/` 目录：`<Name>.tsx` + `<Name>.css` + 头部注释，并在 `REGISTRY.md` 登记。既有页面级样式仍在 `styles/`，随改动逐步迁移。
- **代价**：过渡期两种位置并存。
- **何时重新评估**：`styles/` 下文件全部迁移完成时。

## D-004 · Album Engine 作为设置里可安装/卸载的独立插件（0.3.0）
- **日期**：2026-10-17
- **状态**：生效中
- **背景**：原先宿主直接携带完整引擎（查看器、生成器、模型），无法按需安装；旧约定是「不引入动态插件加载」。
- **决定**：用户明确要求后，3D 引擎改为官方可安装插件（固定官方 ZIP + SHA-256 目录，不接收任意 URL/上传）；宿主只保留插件生命周期、资产授权、数据协议校验与 `storage.py` 持久化事务。依赖 `@diedu/album-engine` 升到 0.3.0（`web/vendor/` tarball）。卸载只移除可执行插件文件，实体文档、贴图、固定模型、镜头参数全部保留。
- **代价**：仓库多两份约 13 MB 制品（插件 ZIP、引擎 tarball），在 `.ai-kit/config.sh` 的 `HYGIENE_ALLOW` 里列为例外；引擎升级需同步更新插件目录与哈希。
- **何时重新评估**：引擎有独立发布渠道、不再需要随仓库携带制品时。
