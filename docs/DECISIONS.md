## D-001 · 接入 ai-kit：存量文件进白名单，新改动照常受检
- **日期**：2026-10-17
- **状态**：生效中
- **背景**：项目早于 ai-kit，存在超过 200 行的文件、集中放在 `styles/` 的样式、含字面量颜色的文件。
- **决定**：这些文件列入 `.ai-kit/legacy.txt`，不受 R1/R2/R10/R11 检查；pre-commit 只检查暂存文件；新文件与新建组件必须满足全部规则。仍保留 `tools/hooks` 数据泄漏扫描并先于 ai-kit 检查运行。
- **代价**：白名单内的文件被改动时不会被拦；需靠评审与逐步拆分把它们移出白名单。
- **何时重新评估**：白名单文件数降到 30 以下，或每次动到某个白名单文件时顺手拆分并移除其条目。

## D-002 · 品牌色与语义色保持不变；颜色仍只经 token
- **日期**：2026-10-17
- **状态**：生效中
- **背景**：ai-kit 的 R1 要求灰度。本产品的黄色主色、深浅双主题与语义色是用户已定案的界面规范（AGENTS.md「界面规则」）。
- **决定**：R1（灰度）不适用于本产品既有界面；R2（颜色只经 token，不写字面量）适用于所有新代码。新增色彩需求先加 token。
- **代价**：无。
- **何时重新评估**：用户明确要求改为灰度视觉时。

## D-003 · 新建/重写的单元组件样式与组件同目录
- **日期**：2026-10-17
- **状态**：生效中
- **背景**：AGENTS.md 原规定样式集中放 `src/styles/<模块>.css`；用户新要求「一个组件一个文件，样式也在文件里，不要堆在同一目录」。
- **决定**：新建或重写的可复用单元组件放 `components/ui/<Name>/` 目录：`<Name>.tsx` + `<Name>.css` + 头部注释，并在 `REGISTRY.md` 登记。既有页面级样式仍在 `styles/`，随改动逐步迁移。
- **代价**：过渡期两种位置并存。
- **何时重新评估**：`styles/` 下文件全部迁移完成时。

- **日期**：2026-10-17
- **状态**：生效中
- **背景**：原先宿主直接携带完整引擎（查看器、生成器、模型），无法按需安装；旧约定是「不引入动态插件加载」。
- **决定**：用户明确要求后，3D 引擎改为官方可安装插件（固定官方 ZIP + SHA-256 目录，不接收任意 URL/上传）；宿主只保留插件生命周期、资产授权、数据协议校验与 `storage.py` 持久化事务。依赖 `@diedu/album-engine` 升到 0.3.0（`web/vendor/` tarball）。卸载只移除可执行插件文件，实体文档、贴图、固定模型、镜头参数全部保留。

## D-009 · 允许 Service Worker 在本机缓存专辑封面，退出登录时清空
- **日期**：2026-10-19
- **状态**：生效中
- **背景**：手机上封面需从家中树莓派经公网逐张下载（约 100KB/张），每次打开都会出现空白格子到封面的可见跳变。封面按内容哈希命名、不可变，缓存风险低于库存数据本身。
- **决定**：`static/sw.js` 对 `/api/cover/` 采用缓存优先，仅保存 200 响应；`web/src/core/cover-cache.ts` 在退出登录时删除 `album-covers` 缓存。会话、交易请求及其他私有 API 响应仍禁止缓存，原「不缓存私有库存」约定相应收窄为本条例外。
- **代价**：封面图片保存在设备本机 Cache Storage 中，设备丢失或被他人访问时可能暴露封面；在其他设备修改密码导致的登出不会清空这些设备上的封面缓存，需手动清除站点数据；Service Worker 无法注册的环境（如内置浏览器面板）下缓存不生效。
- **何时重新评估**：封面需要按设备或按用户隔离、或改为服务器侧缩略图缓存时；或发现 Service Worker 在目标设备上缓存行为异常时。

## D-010 · 发布脚本：预检、按 schema 恢复快照、快照轮换、公网检查
- **日期**：2026-10-19
- **状态**：生效中
- **背景**：`tools/deploy.sh` 能自动快照与回滚，但服务器上积了 40 份发布前快照（518MB），回滚只切代码不管库结构，发布不看工作树是否干净、测试是否通过，也不检查公网入口。
- **决定**：本机构建时先做预检（未提交改动中止、未推送警告、默认跑测试、构建产物须与已提交的 `static/` 一致）；回滚时若库 schema 已被新版本改动则先恢复发布前快照；发布成功后只保留最近 `KEEP_SNAPSHOTS` 份快照；可选 `PUBLIC_URL` 公网检查（失败退出码 3，不回滚）；锁记录持有者并给出 `--unlock`；服务器 `deploy.log` 记录每次发布；ssh 复用连接；个人默认值写 `data/deploy.env`。补丁更新器走 `DEPLOY_HOST=local` + `PACKAGE_PATH`，不读配置、不做预检。
- **代价**：默认发布更慢（多跑一遍测试，约 1 分钟，可 `--skip-tests`）；旧快照在下次发布时会被一次性清理（按 5 份保留）；自动恢复快照只在 schema 变化时触发，同 schema 的数据迁移问题仍需人工判断。
- **何时重新评估**：增加多台服务器、或改用容器发布时。

## D-012 · 按副本准备售卖草稿，独立 ChatGPT OAuth 优先
- **日期**：2026-10-19
- **状态**：生效中
- **背景**：用户要求识别已有照片的版本与外观，生成人工闲鱼发布所需文案和图片包；确认只做到复制、下载，并明确选择优先官方 ChatGPT OAuth、保留兼容 API。
- **决定**：仅在交易模块增加售卖辅助；不恢复 D-005 删除的照片录入、旧识别路由或实体生成。观察附照片编号，版本沿现有目录检索，不自动选版；核对后显式生成正文。草稿以副本字段保存，不改上架状态，显式上架与草稿同一事务；导出只含有序选图。复用现有抽屉、Dropdown、灯箱与下载工具。
- **模型与认证**：新增单职责标准库服务，经 Services 注入。官方 SIWC 独立动态客户端、PKCE/state/nonce、固定 issuer/JWKS 的 RS256 校验；loopback 本机授权，自托管用本机 CLI 授权后安全导入，保留目标 host ID。账户凭据以权限受限文件保存并串行刷新，业务库与备份不含令牌。API 使用服务端环境变量，需显式切换；失败不切换计费来源。
- **代价**：官方订阅调用处于预览协议，账号模型与权限需现场核验；新增纯标准库 RS256 校验需覆盖签名/issuer/audience/nonce/有效期。进行中的任务保存在内存，服务重启需重试；已保存草稿可恢复。图片细节受原上传压缩限制。根模块新增 domain_listing.py，已同步 Docker 与发布包校验器；旧更新器尚不认识该根模块时需手动部署本版。
- **何时重新评估**：官方 OAuth 协议变化、需要跨实例任务恢复、闲鱼上传规则变化，或用户要求自动填表/发布时。

## D-014 · 条码检索增加 Discogs 备用来源与手动录入未收录版本
- **日期**：2026-10-19
- **状态**：生效中
- **背景**：日版 IECP-50008（Red，2008）等版本 MusicBrainz 未收录；检索无结果后表单无出路，MusicBrainz 偶发限流 503 时也只提示“暂时不可用”，用户无法录入。
- **决定**：MusicBrainz 优先；无精确匹配或不可用时查 Discogs 公开接口（精确条码 / 目录号、仅 CD，候选仍须人工选择，不按标题猜）。接口返回各来源状态；两来源都不可用才报错，都没有则前端提示并提供手动录入。新增 `discogsReleaseId`、`manualRelease` 两个发行资料字段；保存时 Discogs 版本按其条码核对，手动版本不核对。前端查询加 70 秒兜底超时，不再无限“查询中”。
- **代价**：Discogs 公开接口约每分钟 25 次，客户端串行 2.5 秒间隔；数据为社区维护，国家名仅映射常见项；无 MusicBrainz ID 的记录没有 CAA 封面、3D 与艺人反查依据，封面靠 iTunes 或手动。手动录入的名称与资料完全由用户负责。
- **何时重新评估**：需要 Discogs 令牌提高限额、要拉取 Discogs 封面，或用户要求将未收录版本回写第三方库时。

## D-013 · 多服务商连接与能力目录；Claude 使用官方 CLI OAuth
- **日期**：2026-10-19
- **状态**：生效中
- **背景**：用户要求同时登录多家服务商，选择 OpenAI OAuth、DeepSeek、Anthropic OAuth 的模型及思考强度。
- **决定**：保留各连接，按服务商/授权身份隔离模型配置和目录；显式拉取模型并校验能力，只提供目录声明的强度，默认省略强度参数。任务持有启动快照，不随界面切换。DeepSeek 用官方多模态 Chat Completions/API Key；OpenAI 复用独立 SIWC/Responses。Anthropic 不冒充其他客户端，不直接借 CLI token 请求 API；使用官方 Claude Code auth 与 print/SDK 协议，通过标准库 subprocess 调用可选 CLI，独立授权目录。使用安全模式禁用自定义上下文，无工具/MCP/钩子，无会话持久化；授权变化与分析/目录读取互斥。配置/密钥在私密文件，状态只返回安全摘要。保持原兼容 API 服务端环境变量路径。
- **代价**：Claude CLI 是可选外部依赖，默认 Docker 无此通道，需用户在同一服务环境安装；CLI 初始化模型目录是版本协议，升级可能变化，失败须更新。服务商未声明图片能力时保留未知，不能宣称实际可用；模型列表不等于账户真实推理成功。订阅/API 计费规则由各家账户决定。DeepSeek 断开设置明确覆盖环境变量，重新连接需显式输入密钥。
- **何时重新评估**：官方提供适合本应用的 Anthropic 直连 OAuth 规范、CLI 目录协议变化或服务商调整视觉/思考能力元数据时。

## D-015 · 专辑详情分层：摘要 + 发行资料页 + 管理页；编辑只放原始信息；数字实体归收藏展示

- **背景**：详情与编辑页经多轮叠加改动，内容按加入先后排列而非按用途：发行信息排在照片和备注之后，上架资料分散，编辑里混着数字实体、上架与存放位置缺口，管理页（底部操作 + 零散字段）混乱且功能不全。

## D-016 · 相机扫条码：引入 barcode-detector（zxing-wasm 垫片），wasm 随站打包
- **日期**：2026-10-21
- **状态**：已实现
- **背景**：查询条码要支持手机相机。浏览器原生 `BarcodeDetector` 在 iPhone Safari 上没有；手机端主要是 iPhone。
- **决定**：前端新增依赖 `barcode-detector`（含 `zxing-wasm`）：有原生支持时用原生，否则首次扫码才动态加载垫片。wasm 作为 `static/assets` 静态资源随站发布，`locateFile` 指向本站，不连外部 CDN（CSP `connect-src 'self'`）。只识别 EAN-13/8、UPC-A/E 并要求 GS1 校验位通过。
- **代价**：构建产物多约 0.9MB 的 wasm（gzip 约 0.4MB，仅扫码时下载）；多一个前端依赖需随版本更新。服务端仍零第三方依赖。
- **何时重新评估**：iOS Safari 原生支持 `BarcodeDetector` 后可去掉垫片。
