## D-001 · 接入 ai-kit：存量文件进白名单，新改动照常受检
- **日期**：2026-10-17
- **状态**：生效中
- **背景**：项目早于 ai-kit，存在超过 200 行的文件、集中放在 `styles/` 的样式、含字面量颜色的文件。
- **决定**：这些文件列入 `.ai-kit/legacy.txt`，不受 R1/R2/R10/R11 检查；pre-commit 只检查暂存文件；新文件与新建组件必须满足全部规则。仍保留 `tools/hooks` 数据泄漏扫描并先于 ai-kit 检查运行。
- **代价**：白名单内的文件被改动时不会被拦；需靠评审与逐步拆分把它们移出白名单。
- **何时重新评估**：白名单文件数降到 30 以下，或每次动到某个白名单文件时顺手拆分并移除其条目。

## D-002 · 品牌色与语义色保持不变；颜色仍只经 token
- **日期**：2026-10-17
- **状态**：生效中
- **背景**：ai-kit 的 R1 要求灰度。本产品的黄色主色、深浅双主题与语义色是用户已定案的界面规范（AGENTS.md「界面规则」）。
- **决定**：R1（灰度）不适用于本产品既有界面；R2（颜色只经 token，不写字面量）适用于所有新代码。新增色彩需求先加 token。
- **代价**：无。
- **何时重新评估**：用户明确要求改为灰度视觉时。

## D-003 · 新建/重写的单元组件样式与组件同目录
- **日期**：2026-10-17
- **状态**：生效中
- **背景**：AGENTS.md 原规定样式集中放 `src/styles/<模块>.css`；用户新要求「一个组件一个文件，样式也在文件里，不要堆在同一目录」。
- **决定**：新建或重写的可复用单元组件放 `components/ui/<Name>/` 目录：`<Name>.tsx` + `<Name>.css` + 头部注释，并在 `REGISTRY.md` 登记。既有页面级样式仍在 `styles/`，随改动逐步迁移。
- **代价**：过渡期两种位置并存。
- **何时重新评估**：`styles/` 下文件全部迁移完成时。

## D-004 · Album Engine 作为设置里可安装/卸载的独立插件（0.3.0）
- **日期**：2026-10-17
- **状态**：生效中
- **背景**：原先宿主直接携带完整引擎（查看器、生成器、模型），无法按需安装；旧约定是「不引入动态插件加载」。
- **决定**：用户明确要求后，3D 引擎改为官方可安装插件（固定官方 ZIP + SHA-256 目录，不接收任意 URL/上传）；宿主只保留插件生命周期、资产授权、数据协议校验与 `storage.py` 持久化事务。依赖 `@diedu/album-engine` 升到 0.3.0（`web/vendor/` tarball）。卸载只移除可执行插件文件，实体文档、贴图、固定模型、镜头参数全部保留。
- **代价**：仓库多两份约 13 MB 制品（插件 ZIP、引擎 tarball），在 `.ai-kit/config.sh` 的 `HYGIENE_ALLOW` 里列为例外；引擎升级需同步更新插件目录与哈希。
- **何时重新评估**：引擎有独立发布渠道、不再需要随仓库携带制品时。

## D-005 · 移除 AI 照片识别与宿主侧数字实体生成
- **日期**：2026-10-17
- **状态**：生效中
- **背景**：AI 照片识别（视觉模型）已弃用；数字实体的生成已全部交给 Album Engine 项目。
- **决定**：删除视觉模型配置、`/api/recognize`、批量照片录入（照片草稿）及其存储方法；删除宿主的数字实体生成入口（`/api/twins/start|cancel|guided`、人工选图编辑器、编辑页的生成/取消按钮）；~~`server/recognition.py`~~ 缩为只做 MusicBrainz 检索的 `server/release_catalog.py`；视觉端口恒为「未配置」。保留：发行版检索、实体与素材的持久化/备份、插件管理、已有实体的附件与盘面校准。
- **代价**：旧数据目录里的 `vision-config.json`、`imports/` 草稿不再使用（不删除）；已保存记录里历史的「识别依据」不再显示（数据仍在）；本应用不再能创建新的数字实体。
- **何时重新评估**：Album Engine 项目提供向宿主发布实体的正式接口时。

## D-006 · 空库首次启动写入两张示例专辑（兼作使用指引）
- **日期**：2026-10-17
- **状态**：生效中
- **背景**：新实例默认是空库，新用户不知道从哪里开始；维护者希望以两张个人喜爱的专辑作为示例（条码 656605892627、796441804320，经 MusicBrainz 核实为 Sufjan Stevens《Illinois》与 Godspeed You! Black Emperor《Lift Yr. Skinny Fists Like Antennas to Heaven!》）。
- **决定**：`server/starter_albums.py` 定义两条示例（名称、艺人、年份、备注指引），由 `app.py` 在非 `--no-seed` 启动时调用 `seed_starter`。仅当库中无任何记录且 meta 标记 `starter-seeded` 未写过时，经 `storage.py` 的 `save` 写入一次；已有数据的实例只记标记、不注入。记录不含买入金额、日期与渠道，成本为 null。
- **代价**：仓库内多一份个人喜好清单（不含任何购买或账号数据）；示例专辑无封面（封面需用户在应用内自行搜索）；删除示例后不会再次出现，需手动在回收站处理。
- **何时重新评估**：需要多套起步数据或用户可选示例时；或示例清单需要随发行版变化时。

## D-008 · 治理文档工程化：统一索引与机械校验

- **背景**：规范与契约文档随代码迁移，出现大量失效路径、已删功能的引用与过时计划（见 D-007、日志 2026-10-17-ai-kit-sync-and-doc-cleanup）。仅靠人工阅读无法及时发现。

## D-009 · 允许 Service Worker 在本机缓存专辑封面，退出登录时清空
- **日期**：2026-10-19
- **状态**：生效中
- **背景**：手机上封面需从家中树莓派经公网逐张下载（约 100KB/张），每次打开都会出现空白格子到封面的可见跳变。封面按内容哈希命名、不可变，缓存风险低于库存数据本身。
- **决定**：`static/sw.js` 对 `/api/cover/` 采用缓存优先，仅保存 200 响应；`web/src/core/cover-cache.ts` 在退出登录时删除 `album-covers` 缓存。会话、交易请求及其他私有 API 响应仍禁止缓存，原「不缓存私有库存」约定相应收窄为本条例外。
- **代价**：封面图片保存在设备本机 Cache Storage 中，设备丢失或被他人访问时可能暴露封面；在其他设备修改密码导致的登出不会清空这些设备上的封面缓存，需手动清除站点数据；Service Worker 无法注册的环境（如内置浏览器面板）下缓存不生效。
- **何时重新评估**：封面需要按设备或按用户隔离、或改为服务器侧缩略图缓存时；或发现 Service Worker 在目标设备上缓存行为异常时。

## D-010 · 发布脚本：预检、按 schema 恢复快照、快照轮换、公网检查
- **日期**：2026-10-19
- **状态**：生效中
- **背景**：`tools/deploy.sh` 能自动快照与回滚，但服务器上积了 40 份发布前快照（518MB），回滚只切代码不管库结构，发布不看工作树是否干净、测试是否通过，也不检查公网入口。
- **决定**：本机构建时先做预检（未提交改动中止、未推送警告、默认跑测试、构建产物须与已提交的 `static/` 一致）；回滚时若库 schema 已被新版本改动则先恢复发布前快照；发布成功后只保留最近 `KEEP_SNAPSHOTS` 份快照；可选 `PUBLIC_URL` 公网检查（失败退出码 3，不回滚）；锁记录持有者并给出 `--unlock`；服务器 `deploy.log` 记录每次发布；ssh 复用连接；个人默认值写 `data/deploy.env`。补丁更新器走 `DEPLOY_HOST=local` + `PACKAGE_PATH`，不读配置、不做预检。
- **代价**：默认发布更慢（多跑一遍测试，约 1 分钟，可 `--skip-tests`）；旧快照在下次发布时会被一次性清理（按 5 份保留）；自动恢复快照只在 schema 变化时触发，同 schema 的数据迁移问题仍需人工判断。
- **何时重新评估**：增加多台服务器、或改用容器发布时。

## D-011 · 发布工具抽成 ai-kit 的 ship，本项目只留配置与兼容入口
- **日期**：2026-10-19
- **状态**：生效中
- **背景**：D-010 的发布逻辑写在本项目的 bash 脚本里，其他项目要用只能复制；bash 脚本也难以测试（macOS bash 3.2、全角字符并入变量名已踩坑两次）。
- **决定**：通用部分移入 ai-kit（`.ai-kit/ship/ship.py`，Python 标准库，配置 `deploy.toml`，测试在 ai-kit 仓库的 test_ship）；本项目新增根目录 `deploy.toml` 与 `data/deploy.local.toml`（个人覆盖），`tools/deploy.sh` 退为兼容层（旧参数与环境变量 → ship，补丁更新器调用方式不变）。发布包带上 `deploy.toml` 与 `ship.py`，`PACKAGE_ROOTS` 与必需文件清单同步。
- **代价**：服务器上运行补丁更新器需要 Python 3.11+（tomllib）；升级 ship 要走 ai-kit 的更新流程（`bash .ai-kit/update.sh`）；个人覆盖文件从 `data/deploy.env` 改为 `data/deploy.local.toml`。
- **何时重新评估**：第二个项目接入 ship 后，按实际差异调整配置项；或需要多台服务器 / 容器发布时（改用 Kamal 等）。
