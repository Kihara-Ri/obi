# 数字实体生成管线：阶段边界与演进契约

2026-10-14 起，宿主数字实体工作流由调度器串联三个独立阶段。每一阶段依赖显式输入，不读取另一个阶段的内部状态。本次重构只重组后端代码，不变更任务备份、实体 schemaVersion=1、用户确认流程或 Album Engine API。

## 流程

~~~mermaid
flowchart TD
  A["DigitalTwinService: 任务领取与租约"] --> B["SourceDiscovery.lookup: 发行版与图源验证"]
  B --> C["SourceDiscovery.prepare: SourceManifest 许可 sourceIds"]
  C --> D["SurfaceUnderstanding.plan: 选择参考图片"]
  D --> E["SourceDiscovery.fetch_images: 仅取许可图源"]
  E --> F["SurfaceUnderstanding.build: 表面映射"]
  F --> G["GeometryAssembly.assemble: 几何与贴图校验"]
  G --> H["Store.update_twin: 事务发布"]
  H --> I["Album Engine: GLB、材质与交互"]
~~~

## 阶段契约

1. **Source Discovery**：由已确认 MusicBrainz 发行版查同版 CAA，核实同版 Discogs（完整条码、目录号和 CD 介质），必要时查同一 release-group 的同封装/同碟数版本。临时 SourceManifest.allowed_ids 限制本次任务可用图源；未知 ID 在任何远程下载前拒绝。借用版次继续保留 sourceReleaseId。
2. **Surface Understanding**：只消费清单和下载的图片数据，调用 PLAN 与 BUILD；不需要 MusicBrainzClient、DiscogsClient 或资源服务器地址。手动绑定的实物 photo:N 必须保留，计划最多 16 张。
3. **Geometry Assembly**：输入 JSON 映射、确认发行版、已下载素材及碟数，使用 clean_entity 校验所需表面、版本来源、四点坐标、曲面形变与盘面参数。输出旧实体格式，不改写上一阶段的映射数据，不访问网络。
4. **Publication**：调度器调用 Store.update_twin，仅在任务 claim 有效、副本未发生影响实体的修改、所有图片文件存在时原子提交 succeeded。失败不覆盖账本或照片。

## 故障隔离

- 来源缺失或封装不兼容：Source Discovery 结束，禁止模型根据标题猜版。
- 模型超时：Surface Understanding 失败，来源与账本数据不变；未来可换成规则、轻量图片分类或手动 Adapter。
- 包装缺少必需图片：Geometry Assembly 要求补图，不伪造不存在的部件。
- 并发覆盖：Store 事务保留旧状态，旧任务不能覆盖新任务。

**本次未实现**：无模型自动 PLAN/BUILD、独立歌词册与侧标部件树、可跨任务恢复的中间产物持久化、图片质量评分。它们属于下一轮功能增量，不应与此无行为变化的解耦混合。
