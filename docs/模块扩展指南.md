# 碟渡模块扩展指南

碟渡提供一套共同的实物副本、照片、搜索、备份和数据写入规则。个人需求可由 Agent 或贡献者增加内置模块，沿用这些规则，不需要重新建立收藏账本。

## 当前模块契约

| 模块 ID | 内容 | 依赖 |
|---|---|---|
| acquisition | 买入日期、渠道、原币金额、费用、成本展示 | 基础收藏 |
| trading | 上架资料、销售单、到账、退款、交易历史 | 基础收藏 |
| circulation | 海外库存、包裹、签收与运费分摊 | acquisition |
| showcase | 收藏展示，使用现有副本与封面展示收藏 | 基础收藏，无购入、交易或周转依赖 |

配置保存在 `meta` 表的 `modules-v1` 键。`POST /api/modules` 接收四个开关组成的完整 `enabled` 布尔字典；为了兼容旧客户端，也接受完整的三个旧业务开关，并补 `showcase: false`。漏任一旧开关、未知项、非布尔值或不满足依赖均返回校验错误。`GET /api/state` 的 `modules` 包含 `enabled`、`configured`、`needsSetup` 与 `startPage`。接口仍使用当前登录、同源校验和写锁，不新增凭据或会话方式。

```json
{"enabled":{"acquisition":true,"trading":false,"circulation":false,"showcase":true},"startPage":"gallery"}
```

`startPage` 可选，只接受 `domestic`（收藏/库存）或 `gallery`（收藏展示），保存为 `meta.start-page-v1`。省略时保留原偏好，旧实例默认为 `domestic`；显式 `null`、其它页面或非字符串均拒绝。模块开关与首页选择在 `storage.py` 同一个事务保存，任一项不合法时都不会部分写入。响应为 `{"ok":true,"enabled":{...},"startPage":"gallery"}`。即使关闭展示模块，保存的 `gallery` 偏好仍保留，前端暂时使用收藏页作为首页；再次启用后恢复该偏好。

无配置时兼容旧实例：三个旧业务模块启用，展示模块关闭，不自动改变用户首页。已保存的三键配置读取时补 `showcase: false`，读取不回写库。没有任何副本、包裹或销售的空白实例显示首次选择页；只有用户保存选择才持久化设置。完整备份保留已保存的配置，恢复旧三键配置时规范化为四键；没有首页设置的旧备份按 `domestic` 处理。现有备份继续使用 schema 4，不因新增模块改变 schema。

关闭模块保留记录、关联、版本号、原币金额与照片。关闭海外周转后，「我的收藏」聚合 overseas/domestic/transit；在途副本保持真实状态，先重新开启模块处理包裹。关闭交易后，销售历史保留，重新开启继续处理。没有购买资料的实物允许保存，成本为 null。

展示是独立可选入口，关闭后收起展示入口与页面，不改写副本或封面、删减备份、合并作品身份，也不清除首页偏好。展示页面的数据来自现有收藏状态，没有另建收藏库存。`core/gallery.ts` 的 `isCollectedRecord()` 统一纳入 domestic/overseas/transit，排除 shipping/sold/trash，不受 listed 或封面缺失影响。九模式结果和放大面板共用这个口径。

## 收藏展示与手动组

展示以手机触屏为主要场景。胶片用原生横向连续滚动，停留位置不吸附；翻阅、唱片箱、扇形展开和环形展架在拖动期间持续沿各自轨道移动，松手后以更强吸附迅速对齐。扇形交接沿原弧线浅转侧，以 CD 盒厚度小幅让位并保留可见封面，不改变停留时的弧线位置或缩放。唱片箱沿竖向翻动，普通一次划动约翻一张，长距离拖动仍可持续翻找。桌面连续向下铺开全部结果；等距墙沿左上↔右下轨道自由停留，仅保留视口附近封面。后两者不分组、不分页。轨道内处理单指平移，轨道外保留页面滚动；保留多指缩放、屏幕边缘返回、指针取消和减少动态效果。

九种布局共用漫游开启状态，iOS 风格状态开关始终位于工具区，开启与关闭时位置一致。「展示设置」先集中排序、封面大小和标题选项，再独立列漫游设置行；该行的速度或间隔按钮仅在漫游开启时显示，通过滚轮设置 2–30 秒，各布局单独保存在浏览器；关闭漫游隐藏展示设置中的速度或间隔入口并保留设置。翻阅、唱片箱、扇形展开与环形展架先按设置停留，再按正常速度切换一张，秒数只改变停留时间；其余五种布局按「秒/张」控制连续滚动速度。默认秒数：封面墙 8、瀑布流 10、胶片 6、翻阅 4、唱片箱 5、桌面铺开 10、扇形展开 4、等距封面墙 4、环形展架 4；已有手动保存的值保留。漫游默认关闭，不持久化为启动状态；开启后只由用户显式关闭，收起展示设置、切换布局、范围、排序或大小不清除开启状态。触碰、拖动和手动浏览暂时避让，抽屉打开或页面后台期间暂停。四种中心布局在操作结束、关闭抽屉或回到前台后重新按设定间隔计时；连续布局在操作结束约 3 秒后继续，关闭抽屉或回到前台后自动恢复。减少动态效果暂停自动运动但保留开启意图，恢复后继续。各布局沿自己的浏览轨迹运动，不引入第二份收藏结果或改写库存偏好。

展示范围是全部、本地艺人或一个手动组；艺人使用本地名称精确匹配，搜索与所选范围取交集，不触发外部身份解析。组成员是独立实物 ID，顺序由用户维护，跨组允许重复；选择组默认按组内顺序，也可选择普通排序。任何范围都继续过滤 `isCollectedRecord()`，组内售出/回收站成员关系保留，但不渲染；不存在的记录 ID 忽略，不复活记录。

`GET /api/state` 的 `settings["showcase-groups-v1"]` 提供以下结构；键缺失时按 `{"revision":0,"groups":[]}` 读取，不自动落盘：

```json
{"revision":1,"groups":[{"id":"11111111111111111111111111111111","name":"展示组","recordIds":["22222222222222222222222222222222"]}]}
```

`POST /api/showcase/groups` 使用既有登录、同源校验与写锁。请求与响应：

| 操作 | 请求字段 |
|---|---|
| create | `action`, `expectedRevision`, `name`, `recordIds`；组 ID 由服务端生成 |
| update | `action`, `expectedRevision`, `id`, `name`, `recordIds`；保留组 ID |
| delete | `action`, `expectedRevision`, `id`；只删除组 |

成功返回 `{"ok":true,"revision":<新版本>,"groups":[...]}`。`expectedRevision` 是整个组清单的非负整数版本；过期写入抛 `ConflictError`，返回 409，并保留前端输入。组名去除首尾空白后为 1–100 字，允许空组；最多 1000 组、每组最多 10000 个副本 ID，同组重复 ID 拒绝。新加入的成员须为已有副本，历史组中的缺失成员可保留。创建、改名、成员增减/重排和删除均经 `storage.py` 单事务写入与审计，事务内重新核验模块与版本；模块关闭时拒绝组写操作。

组沿用 meta 表和 schema 4，随完整备份与恢复保存；恢复先严格校验新键的结构、类型与重复 ID，再执行任何写入。旧备份无该键即无组；关闭模块不会删组。布局、筛选范围和排序仍是浏览器偏好，组内容和顺序为服务端资料。

## 包装结构与模型贴图

每张实物副本可在记录 JSON 中保存 `packaging`，通过现有 `POST /api/records` 与 `storage.py` 的事务写入；不改 SQL schema、不新增专用接口。`version` 保留原碟盒文字，`pressing` 与 `obi` 语义不变。展示名称优先采用确认后的结构；旧记录只对明确专业名称/结构别名提供默认模型，紙ジャケット、纸盒、Mini LP 等含糊原文提供候选，不自动写回。包装资料不按同名专辑共享。

字段契约：

- `structure`：`jewel`、`card-sleeve`、`gatefold`、`digipak`、`digibook`、`rigid-box`；`unknown` 显式标记待核对，优先于旧名称的默认识别。
- `thickness`：`slim`、`standard`、`thick`；`discs` 为 1–4，与盒厚独立。
- `panels` 为模型的物理板片数 2/3/4，对应专业包装的 4-panel / 6-panel / 8-panel 印刷面数。
- `pockets`：`left`、`right`、`both`；`holder`：`tray` 或 `pocket`；`tray`：`clear`、`black`、`white`。
- `pocketOpening`：`outer`（朝外边开口）或 `inner`（朝书脊开口），未提供时模型采用 `outer`，不回写旧记录；Gatefold Sleeve / Digisleeve 的纸袋结构可在表单确认方向。其它结构保留已保存的字段，但不提供无效的开口选择。双 CD 内开口对折套仍用 `panels:2`、`pockets:'both'`、`holder:'pocket'`、`discs:2`，不把两块折页误存成四块。
- `finish`：`uncoated`、`matte`、`gloss`；`miniLP`、`slipcase` 为独立布尔属性。
- `size` 为完整 `{width,height,depth}`，单位 mm；宽 50–500、高 50–700、厚 .1–300，必须是有限数字。
- `photos` 的键为 `front/back/spine/insideSpine/insideLeft/insideRight/insideCenter/insideExtra/disc/disc2/disc3/disc4/outer`，值为本副本现有照片的零基序号，必须小于 `photoCount`。`spine` 为外侧书脊，`insideSpine` 为内侧折脊；内开口纸套使用独立印刷面，不把外侧文字印在内折脊。多碟盘面分别指定，不复制第一张盘面；照片仍只存文件系统。
- `photoRegions` 为可选的按上述照片角色保存的四角区域：`[TLx,TLy,TRx,TRy,BRx,BRy,BLx,BLy]`，坐标相对于完整原照片，左上原点，宽高各归一到 0–1。必须恰有八个有限非布尔数字，四点依次围成非退化的凸四边形；交叉、凹形、共线及越界区域均拒绝。运行时用投影 UV 将印刷区域绑定模型，不裁切、拉直、重绘或替换照片文件；原图及照片灯箱仍保留完整实物图。`front` 未指定照片时区域可作用于已有封面；其它角色缺少 `photos` 引用时仍为缺图，不从正面继承来源。编辑器暂不提供数字坐标录入，已有区域随资料保存。

编辑器提交的显式 `photos` 贴图映射针对保存后的照片顺序。旧客户端只改实物照片而不提交 `packaging` 时，服务端按保留的旧照片身份重排映射；删除的照片解除绑定并移除其角色区域，新照片不继承旧贴图或区域。改选或清空贴图角色也清除该角色旧区域，其他角色不受影响；未映射照片的 `front` 封面区域在照片重排时保留。非法类型、尺寸、四角区域或不存在的照片引用拒绝整个事务，原记录/图片保持不变。完整备份保存并校验这些可选字段；缺少它们的旧备份保持可恢复；`packaging:null` 显式清除附加资料。

碟渡保留 `web/src/core/album-packaging.ts` 的旧文字解析与业务编辑规则；包装归一化调用引擎轻量入口。展示直接消费当前有效发布结果中的 canonical `document`，不再经 `AlbumRecord.model*` 往返构造实体。历史 v1 只读兼容，归属可确定时由引擎 normalize；含糊附件维持 2D，不自动补槽位、落库或生成。

引擎 `AlbumDocument`（schemaVersion 2）以稳定组件 ID、`assembly.root`、`parent`、`mount`、`contains` 和不透明 assets 表达完整实体。结构唯一来源为引擎 `schema/album-document-v2.schema.json`，TS 类型和 Python 校验共享它；`src/contracts/model-set.json` 定义模型与语义槽位。尺寸用毫米、角度用弧度；只在引擎装配入口转米，区分 template/measured 及来源。槽位管理局部坐标、容积、开口及抽出路径；宿主不传任意偏移或以整个场景包围盒猜纸板尺寸。OBI/歌词本/内袋/CD 的包容、遮挡、raycast、轨迹及镜头共用装配结果。

九种布局和平面灯箱先显示 2D，能力检查通过才显示 2D/3D；点击 3D 的同一手势中请求感应，再加载查看器与模型。失败经 `onUnavailable` 返回 2D；切回、换张和关闭释放资源，引擎不保留 CSS 模型及其公开入口。盘面校准由引擎 `editor` 导出，在编辑专辑挂载，宿主提供保存回调；展示不放校准入口。

所有包装及附件都在引擎用 Blender 制作、真实导出 GLB：源脚本与产物在 Album Engine 项目中维护（宿主不含模型构建脚本）。原 21 个库模型加三个 OBI/歌词本/内袋组件模板一起分发。运行时仅加载并装配模板，设置其已制作的形状键、节点尺度、材质与变换，不用 Three.js 即席造附件网格。nominal 模型边界是模板几何，不称实物测量。模型 rigVersion 1 与文档 schemaVersion 2 独立版本化；坐标、轴心、印刷材质/extras 变化须有兼容策略。

### 唱片实体引擎与更新

当前为 Album Engine 0.3.0 官方可安装插件。设置负责安装/卸载，未安装时基础账本与 2D 正常工作；插件包、数据导出、模型固定、跨窗口 revision、备份边界与开发步骤以[Album Engine 插件契约](AlbumEngine插件.md)为准。所有 3D 源码只在引擎项目维护，宿主不再静态打包查看器或复制 GLB；`vendor/album_data/` 仅为纯数据协议，历史 runtime 兼容副本不进入发行包。


## Agent 应先阅读与修改哪些入口

### 手动生成数字实体

GET /api/twins 返回服务配置和各副本任务，POST /api/twins/start 仅使用已保存 MusicBrainz Release ID。条码编辑需要 MusicBrainz 完整校验；确实没有条码的发行版由 Catalog Number 检索并选定 UUID。不从照片 OCR 条码，不在数字实体生成阶段重复搜索或确认候选，也不再提供 POST /api/twins/confirm。POST /api/twins/cancel 保留，图集预览需要登录。
接口均需登录，写操作由模块开关限制；图集预览经 `/api/twin-review-assets/<job>/<asset>` 提供，成品图片经 `/api/twin-assets/<job>/<asset>` 提供，两者均受保护，未登记工作文件不可访问。

任务存入现有 meta 的 `digital-twins-v1`，不改 SQL schema。创建、领取、心跳、取消和发布都经 `storage.py` 的短事务；同副本活动任务唯一，requestId 收据在完成后仍可查询，旧 expectedJobId 不会开启新一轮。工作令牌与期限跨进程协调；过期或重启中断需人工重试，不能自动重复调用模型。恢复备份会撤销在途令牌。

输入照片在提交时复制为不可变任务快照，源照片不变。发布前核对包装、身份与照片序列；照片有专用 photoRevision，不用成本/笔记的普通记录 revision 误判模型过期。材料缺失、版本冲突或校准坐标非法时停在 2D。共享模板与旧 packaging 资料并不等于已生成实体，有效发布结果还须通过引擎完整能力检查，才允许用户从默认 2D 显式切换 3D。

素材规划除本副本照片与 CAA 外，可读取已确认 MB release 的 `url-rels` 中精确 Discogs release 关系；条码、目录号、CD 介质一致才冻结其结构说明与图集。角色 ID 为 `discogs:<releaseId>:<index>`，与 CAA/照片合计最多 16 张进入 BUILD。CAA 类型仅作线索，册页、外包装、OBI 仍按结构证据区分，不将同版参考磨损宣称为本副本。

实体可选协议（不写回原 `packaging`）：`surfaces[role].warpRows` 为 2–17 行 `[leftX,leftY,rightX,rightY]` 原图归一化坐标，两侧高度严格递增、每段凸且边界不自交；有字段时优先于 `region`。`calibration.spine` 输入为 `{widthRatio,sourceId,basis:"image-estimate",reliefMm?}`，只支持 gatefold/digipak/digibook；widthRatio 为同平面展平外脊与单块封板宽度比，限 0.001–0.2。可选 reliefMm 为沿高度等距的 3–17 个有限近似值，限 ±0.15 mm，不从印刷亮度生成。服务端发布时把 sourceId 换为真实 `asset/sourceUrl/origin` 证据，备份与恢复保留映射和校准来源。

展示直接消费 canonical document 的印刷面与校准；旧字段仅保留兼容读取，不能确定附件归属的旧实体维持 2D。纸脊、轴心与开合形状同步校准，120 mm CD 及最小袋腔间隙不缩放，空间冲突时限制收窄并保留警示；尺寸仍仅来自实测。Codex 标准库脚本输入与行为见 [引擎插件与开发边界](AlbumEngine插件.md)，网站视觉 agent 仅返回 JSON。

入口为编辑表单中的 `TwinControls.tsx`、AppContext 内的 `useDigitalTwins.ts`、服务入口 `server/engine_plugins.py`，生成及权威 skill 位于已安装插件的 `runtime/album_engine/`。前端只提交与读状态，使用同请求编号确认断线提交，按版本丢弃迟到响应；页面切换不取消工作。并发、恢复、发布及权限合同见 `tests/test_digital_twins.py`；可执行脚本合同见 `tests/test_album_digital_twin_skill.py`，真实模型校准与手机实机仍要分别验收。

### 通用模块入口

1. 阅读根目录 `AGENTS.md` 和 `AI开发复盘.md`，理解副本独立、金额未知、分摊、上架与位置分离的既定规则。
2. 在 `domain.py` 维护模块配置校验与依赖，在 `storage.py` 的事务中保存配置和业务对象；业务写操作通过 `require_module()` 检查能力。新 API 只登记在 `server/routes.py`。
3. 在 `web/src/core/modules.ts` 声明模块、预设、页面和展示规则。在 `AppContext` 读取服务端配置，组件、页面、表单按单向依赖调用，禁止各自保存第二份开关。
4. 修改所有入口：桌面导航、手机导航及更多页面、账本概览、卡片/列表、详情、批量浮条、单张和批量表单、统计。隐藏字段不应在编辑时被置空或自动填成今天。
5. 按所属模块维护样式和文档，执行后端测试、前端类型检查和构建、临时实例浏览器验收。涉及镜像输入时按项目标准验证 Docker 构建。

内置模块目前随框架一起发布，通过设置开启，尚未定义第三方插件安装协议。购入/运输目前支持 JPY/CNY，交易及统计以人民币记账。新增币种需要贯穿保存、汇率、分摊、导出与展示，不能只增加一个前端选项。

## 上架资料接口

`POST /api/bulk` 的 `action: "list"` 可额外提交 `listing: {channel, url}`，同时保存平台/链接并标记上架。只允许 http/https 商品链接；副本编辑表单不能修改这些字段。`unlist` 取消标记但保留资料。它记录外部发布页面，不自动创建或同步平台商品。

`storage` 为实物存放位置，`location` 为购买渠道。专辑 CSV 保留原列顺序，在末尾增加存放位置、上架平台与商品链接；完整备份始终包含关闭模块的数据。

## 代表性验收场景

- 新用户选择纯收藏：只填名称和艺人保存；单张/批量表单不出现价格、店铺或入库国家；搜索可找到存放位置；照片和独立副本不受影响。
- 收藏与购入：金额或日期可未知，成本不归零；日元购买在未启用海外周转时也进入我的收藏。
- 只启用二手交易：可上架、售出、确认到账，只显示销售金额，不要求补成本，不显示利润。
- 海外周转：批量打包、原币运费、尾差守恒、签收、销售和到账沿用原流程。
- 模块切换：原副本、包裹、销售、照片和原金额不变；禁用能力的旧请求明确失败；重新开启可以继续处理。
- 收藏展示：可在三个业务模块均关闭时单独启用；关闭与重新启用均保留副本、照片和成本未知状态。
- 手动组：独立副本与顺序读回一致、允许跨组重叠；手机/电脑刷新共用，旧版本写入报冲突，删除组不删副本；售出/回收站成员隐藏，恢复后再显示，备份恢复保留顺序。
- 连续触控：按住并拖到轨道中间时封面已移动；四种中心布局松手后迅速吸附对齐，唱片箱普通一次划动约翻一张，胶片/等距墙可停在非整张位置；桌面滚动覆盖全部结果。另查轨道外滚动、多指缩放、边缘返回、取消与减少动态效果。
- 自动漫游：九种布局均沿各自轨迹运动；收起展示设置、切换布局、筛选及改变排序/大小保留开关。四种中心布局在触碰/拖动或手动浏览结束、关闭资料抽屉后及回到前台后重新按设定间隔计时；连续布局在操作结束约 3 秒后继续，抽屉关闭或回到前台后自动恢复。减少动态效果暂停运动但保留开关。滚轮速度按布局保存，刷新或重开页面只恢复速度，漫游默认关闭。
- 首页：用户可选收藏或展示；省略不覆盖选择，关闭展示保留原偏好，非法首页与模块配置一起拒绝，浏览器返回不覆盖个人首页选择。
- 备份与恢复：配置和业务资料一起还原；旧备份无模块设置时保持三个旧业务模块启用且展示关闭，旧三键配置补 `showcase: false`，不合法模块依赖或首页在写入前拒绝。

自动化契约见 `tests/test_modules.py`、`tests/test_showcase_groups.py`，HTTP 登录和禁用操作的验收见 `tests/test_web_app.py`；`npm --prefix web test` 验证展示状态范围、独立副本、筛选、浏览器偏好与轨道模型。连续拖动的中间状态、释放/取消、漫游暂停及移动端操作另须浏览器验收；真实手机的跟手与帧率单独核对，不能由模拟窄屏结果推定。这些场景使用临时数据，不能通过真实用户库做试验。

当前 3D 模型集只对 Blender 模板尺寸保证完整装配；实测尺寸与模板不同则保留原资料并使用 2D，待引擎增加对应模型与整件净空验收后再开放 3D，不能整体缩放光盘来适配。
