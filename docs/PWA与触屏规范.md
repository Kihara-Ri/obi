# PWA 与触屏规范

手机主屏幕网页应用（iOS 添加到主屏幕、安卓外壳 WebView）上出过的问题，以及以后怎么避免再犯。每条都按「现象 → 原因 → 现行做法 → 规则」写；规则是硬性的，改动涉及这些地方时先读对应小节。

能机检的规则在 `web/tests/pwa-guards.test.mjs`（随 `npm --prefix web test` 运行）；手感、系统手势、键盘、刘海位置只有真机能证明，浏览器模拟通过不算验收。完整的视觉与组件规范见 Claude 设计系统「Obi 设计系统」（与本文同一套规则），颜色、动效时长以 `web/src/styles/tokens.css` 为准。

## 1. 状态栏与刘海

- **现象**：顶栏被状态栏压住，或内容滚上去从时间、电量后面透出来；安卓沉浸展示时状态栏仍在并占高度。
- **原因**：`viewport-fit=cover` 让页面铺进刘海区，安全区要自己让；网页的 `requestFullscreen` 与安卓外壳隐藏系统栏互相争抢，部分 ROM 失焦后会唤回系统栏；外壳只在次版本更新（D-023），补丁版改了原生代码等于没改。
- **现行做法**：`index.html` 的 viewport 带 `viewport-fit=cover`，`theme-color` 按深浅各一份（`static/theme.js` 随所选主题改写）。手机顶栏 `.page-head` 吸顶在 `--head-top = max(10px, 安全区顶 + 4px)`，`::before` 从屏幕顶铺到顶栏下沿再渐隐，盖住状态栏一带。底栏 `--nav-bottom = max(8px, 安全区底 − 14px)`。安卓沉浸只走外壳的原生桥，不调网页全屏。
- **规则**
  - 任何贴屏幕边缘的固定元素都要加该边的 `env(safe-area-inset-*)`：顶部用 `calc(Npx + env(safe-area-inset-top))` 或 `max()`，不能写死 `top:0`。
  - 吸顶元素必须有不透明（或渐隐）底盖住状态栏带，不能让内容从状态栏后透出。
  - 新增主题底色时同步改 `theme-color` 与 `theme.js`。
  - 动安卓系统栏、沉浸、权限、桥接 = 改 `android/`，必须升次版本（D-023）。
  - 安全区在桌面浏览器里模拟不出来，位置只能在真机上确认。

## 2. 双指缩放与自动放大

- **现象**：双指一捏整页放大，布局错位、固定抽屉抽搐；点小字号输入框时 iOS 自动放大页面，收起键盘后不复原。
- **原因**：iOS Safari 不理会 `user-scalable=no`；iOS 对小于 16px 的输入框聚焦时自动放大。
- **现行做法**：`html{touch-action:pan-x pan-y}`（不含 pinch-zoom）+ `main.tsx` 拦 `gesturestart`；灯箱、等距和轨道布局的捏合用自己的指针事件，在局部容器上恢复 `touch-action`。手机断点内 `input,select,textarea` 统一 16px。
- **规则**
  - 不要删 `gesturestart` 拦截，也不要给 `html` / `body` 加回 `pinch-zoom`。
  - 需要缩放的区域自己实现，并只在那个容器上设置 `touch-action`。
  - 手机上会被直接聚焦的文字框不得小于 16px。抽屉里的文字框由 `useFloatingFields` 改走 `FocusInput`，原框不聚焦，才允许更小的字号。
  - 「展示页支持多指缩放」指的是展示布局内部自己的捏合，不是整页缩放。

## 3. 橡皮筋与滚动穿透

- **现象**：整页被拉得变形回弹；短表单抽屉里上下滑动，背后页面跟着滚、抽屉抽搐。
- **原因**：抽屉内容不够长时没有可滚动的元素，iOS 把竖向滑动变成文档滚动、平移可视视口；`overscroll-behavior:contain` 只管滚动链，管不了「根本没有可滚动元素」的情形。曾经键盘适配平移面板、防滚动又把 `scrollY` 钉回，两者每帧互相拉扯。
- **现行做法**：`html` / `body` 禁橡皮筋；抽屉打开时锁文档滚动，内容到顶时下拉、到底时上推的 touchmove 才拦截，中段放行。
- **规则**
  - 不要用 JS 去抵消 WebKit 对可视视口的平移（`translateY(visualViewport.offsetTop)` 这类做法已经整体删除，2026-10-28）。
  - 新的浮层或全屏层都要锁背后滚动，并在没有可滚动内容时拦掉 touchmove。

## 4. 左右滑动、边缘返回与切页

- **现象**：
  - iOS 左缘右划把整屏快照连同顶栏、底栏一起滑走，和「顶栏不动，只动内容」的设计冲突。
  - 慢慢右划到一半时内容突然弹回，随后系统播放自己的返回动画。
  - 抽屉侧滑停在一半，之后手势全部失效。
  - 安卓返回键直接退到桌面。
- **原因**：
  - 网页不能定制系统手势的动画。
  - 方向判定前没有 `preventDefault`，iOS 趁这几帧接管手势，页面收到 `touchcancel`。
  - 手势监听依赖每次渲染都会新建的回调，渲染一次监听就被拆掉重挂，跟手状态丢失。
  - 子页是用 replace 进来的，历史里没有上一级，安卓返回键无处可退。
- **现行做法**：
  - 手机切页走 `core/nav.ts`：底栏、顶栏切页一律 `location.replace`，历史里没有可退的条目，系统右划也就无处可退。「更多」的子页在安卓上压一条历史，给返回键用；iOS 不压，返回由自己的手势处理。
  - 左缘手势只有 `core/edge-swipe.ts` 这一份实现：左缘 28px 内起手就拦截（贴边的按钮和链接除外），方向锁定前的 touchmove 也拦；拖过宽度 30% 或快速甩动算返回；`touchcancel`、多指、丢失 touchend 时一律回弹。
  - 抽屉层 `touch-action:pan-y`，告诉 iOS 这里只有纵向手势；内部的横向条带单独恢复 `pan-x`。
  - 展示页左右切换专辑：横向位移至少 48px、横向是竖向的 1.5 倍以上、700ms 内完成才算。列表行左滑操作统一用 `SwipeRow`。
- **规则**
  - 页面里不许直接写 `location.hash = …`，切页只经 `navigate()`（有机检）。
  - 新的横滑手势必须复用 `edge-swipe.ts` 或 `SwipeRow`，不另写阈值。
  - touchstart / touchmove 监听要声明 `{passive:false}` 才能拦系统手势；监听只挂一次，最新状态经 ref 读取。
  - 每个手势都要处理 `touchcancel`；收尾时清掉内联的 transform。
  - 横滑容器只接管横向，竖向滚动交还浏览器（`touch-action:pan-y`）。
  - 慢划、快甩、划到一半松手、被系统打断这四种情况，只有真机能验。

## 5. 长按

- **现象**：长按底栏或返回按钮弹出 iOS 的链接预览，菜单里的「打开」会在新页面里打开应用；长按还会选中文字、出现放大镜或拖起图片。
- **原因**：应用内导航是 `<a href="#…">`，iOS 对链接默认提供预览菜单；文字和图片默认可以选中、拖动。
- **现行做法**：`a[href^="#"]{-webkit-touch-callout:none}`；底栏链接与 `.head-back` 另加 `user-select:none` 和 `-webkit-tap-highlight-color:transparent`；抽屉头部不可选中；展示封面加 `user-select:none` 和 `-webkit-user-drag:none`。
- **规则**
  - 应用内跳转只用 `#` 开头的链接或按钮，不写会被当成外部地址的 href。
  - 新的可点按导航元素加 `-webkit-touch-callout:none`，以及 `user-select:none`、去掉点按高亮。
  - 需要长按做事的元素（比如以后的长按菜单）自己处理 `contextmenu`，同时关掉 callout。
  - 真正的外链明确写 `target="_blank"`，文字后带 ↗。
  - 需要单点唤起外部 App 且禁止链接预览的入口使用原生按钮。链接导航在点按的用户手势内同步触发。
  - 闲鱼入口在手势内先尝试打开 App 的商品地址。页面隐藏或离开时取消网页回退。未能唤起时只在当前窗口打开商品网页。

## 6. 键盘

- **现象**：键盘弹起后盖住输入框；抽屉先上移再被拉回；点输入框时页面抽一下。
- **原因**：WebKit 会平移可视视口来露出输入框，代码再去抵消就会来回打架；抽屉里的滚动容器不会被 WebKit 自动滚到键盘上方。iOS 只在用户手势内同步调用 `focus()` 时才弹出键盘。
- **现行做法**：手机抽屉里的文字框点一下后，在键盘正上方升起独立的 `FocusInput`（portal 到 body，背后页面不动）。专辑名和艺人用 `FocusField`；`data-native-input` 可以退出这个机制。打开即在 layout effect 里同步聚焦。触屏上打开表单不自动聚焦第一个字段。
- **规则**
  - 手机上新增的文字输入默认走 `FocusInput` / `useFloatingFields`，不要自己做键盘避让。
  - 需要弹键盘的聚焦必须在点击手势里同步完成，不能放在 `await` 之后。
  - 数字键盘打开时整段选中旧值，直接输入即替换（金额框的定案）。

## 7. 视口高度

- **现象**：满屏层底部被工具栏或 Home 条遮住，或者出现多余的滚动。
- **原因**：iOS 上的 `100vh` 取的是工具栏收起时的大视口高度。
- **规则**：最小高度用 `100svh`，全屏覆盖层用 `100dvh`，并先写一行 `100vh` 作为旧浏览器的兜底（有机检）。只在桌面出现的侧栏不受此限。

## 8. 悬停与聚焦残留

- **现象**：手指点过的卡片停在抬起状态；弹窗自动聚焦的按钮外面多一圈黄框。
- **原因**：触屏上点按后 `:hover` 会一直粘着；`autoFocus` 会触发 `:focus-visible`。
- **规则**
  - 带位移或缩放的悬停效果只写在 `@media (hover:hover) and (pointer:fine)` 里，或者在 `(hover:none)` 里复位（有机检）。
  - 触屏的按下反馈只改背景或用 `:active` 轻微缩放，不做抬起。
  - 手机底栏在按下时保持图标、文字和计数的尺寸。
  - 触屏上全局关闭 `:focus-visible` 描边（`base.css`），键盘用户仍然能看到描边。

## 9. 主题与旧 WebView

- **现象**：华为 nova 7 永远是深色，切换无效；黄底按钮上的文字也是黄色，看不见。
- **原因**：旧 WebView 不认 `light-dark()`，整条声明作废；黄底上用了「强调色文字」`--accent-text`，而不是黄底专用的 `--accent-ink`。
- **规则**
  - 主题 token 只在 `tokens.css` 里按三段普通声明写：浅色默认、系统深色的 media、显式 `data-theme`。
  - 不用 `light-dark()`（有机检）。`color-mix()` 这类新语法只许用在丢了也不影响阅读的装饰上（比如标签的淡底和描边），文字颜色不能依赖它。
  - 黄色填充上的文字一律用 `--accent-ink`。
  - CSP 禁止内联脚本和样式，主题初始化只能放在 `static/theme.js` 这个阻塞外链脚本里。

## 10. 只能在手势里做的事

- **现象**：分享照片没反应，系统拒绝弹出分享面板。
- **原因**：iOS 要求 `navigator.share`、剪贴板写入、相机授权、全屏都在用户手势内同步调用，先 `await` 取数据再调用就会被拒绝。
- **规则**：需要的数据提前取好（照片在打开详情时就预取），点击时同步调用；数据没准备好时按钮禁用，不要先显示可点再失败。

## 11. 切页快照与闪烁

- **现象**：切页时旧页上的封面闪一下空白。
- **原因**：快照克隆里的 `<img>` 要重新解码，第一帧会画成空白。
- **规则**：旧页快照经 `core/ghost-images.ts` 把视口内已加载的封面换成画好的 canvas。新做的快照或克隆动画也要这样处理；切换期间锁住纵向滚动，结束后清掉所有内联样式。

## 验收清单（涉及上面任一处时）

1. 运行 `npm --prefix web test`，`pwa-guards` 全部通过。
2. 浏览器手机视口（390 和 340 宽，深色和浅色）：无横向溢出、控制台零报错；动画结束后再截图（抽屉 0.22s，切页约 0.46s）。
3. 告诉用户哪些只能在真机上确认，至少包括：
   - 刘海和 Home 条的位置
   - 慢划返回
   - 键盘弹出
   - 长按菜单
   - 安卓返回键
   - 在日志里写明未在真机验证的项目。
